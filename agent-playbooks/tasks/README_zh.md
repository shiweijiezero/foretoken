# 优化任务

[English](README.md) | 简体中文

这里定义常用优化任务的目标、范围、约束与交付结果。用户选择任务并提供环境和必要约束，Agent 按[通用流程](../README_zh.md#使用步骤)完成分析、设计、实现、验证与记录。

## 自主执行

在任务范围和资源预算内持续推进，以目标达成和实测结果作为完成依据。

- 主动完成调查、设计、实现、部署、评测与结果分析；自行解决能够处理的问题，继续执行已经明确的后续工作。
- 每轮根据证据选择下一步。方案无效时分析原因、调整或换一种方案；得到局部收益后，继续检查距目标还有哪些差距。
- 将代码改动、服务启动和单次测试视为过程进展，而不是任务完成。结论应有实际负载下的性能和质量结果支持。
- 持续更新实验记录。结束时说明目标达成情况、保留的改动和结果位置；预算耗尽或遇到无法自行解除的阻塞时，说明具体原因及恢复工作所需条件。

例如：可用资源为 2 台各配 8 张 C500 的服务器。以 Qwen3.5-35B-A3B、BF16、单副本两卡张量并行（TP2）为起点，在 8192 输入 token、512 输出 token、单并发的负载下自主优化 12 小时，探索并行配置与推测解码，持续迭代并汇总吞吐和延迟变化。

使用单台服务器的 2 张 C500，以 BF16、TP2 部署 Qwen3.5-35B-A3B，在 8192 输入 token、512 输出 token、单并发的负载下，将平均每个输出 token 的生成间隔（TPOT）降至 5 ms 以内。

使用 2 台各配 8 张 C500 的服务器，以 BF16 运行 Qwen3.5-35B-A3B，比较聚合部署与预填充/解码分离。在 8192 输入 token、512 输出 token、并发 16 的负载下，用 12 小时将 P95 首 token 延迟降至 1 秒以内，达标或时间预算用尽时汇总结果。
