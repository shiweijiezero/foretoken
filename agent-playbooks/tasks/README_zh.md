# 优化任务

[English](README.md) | 简体中文

这里定义常用优化任务的目标、范围、约束与交付结果。用[任务模板](../templates/task-template_zh.md)填写模型、资源、负载与目标，Agent 按[通用流程](../README_zh.md#使用步骤)完成分析、设计、实现、验证与记录。

## 自主执行

在任务范围和资源预算内持续推进，以目标达成和实测结果作为完成依据。

- 主动完成调查、设计、实现、部署、评测与结果分析；自行解决能够处理的问题，继续执行已经明确的后续工作。
- 每轮根据证据选择下一步。方案无效时分析原因、调整或换一种方案；得到局部收益后，继续检查距目标还有哪些差距。
- 将代码改动、服务启动和单次测试视为过程进展，而不是任务完成。结论应有实际负载下的性能和质量结果支持。
- 持续更新实验记录。结束时说明目标达成情况、保留的改动和结果位置；预算耗尽或遇到无法自行解除的阻塞时，说明具体原因及恢复工作所需条件。

## 举例

自主探索 12 小时：

```text
模型：Qwen3.5-35B-A3B
精度：不限
部署形态：不限
单服务配置：由 Agent 选择 GPU 数和并行方式
可用资源：2*8 卡 C500，可分配给并行实验
评测负载：由 Agent 选择，覆盖不同输入输出长度、并发和自然对话
优化目标：提升吞吐、降低延迟，比较各组负载的性能与回答质量
可改动范围：不限
工作与结束条件：持续优化 12 小时
交付结果：保留方案、代码改动、各组结果对照与实验记录
```

若以单负载指标为目标，沿用上例并调整以下条件：

```text
精度：固定 BF16
部署形态：聚合部署
单服务配置：固定单机 2 卡、TP2
评测负载：8192 输入 token、512 输出 token、单并发
优化目标：平均每个输出 token 的生成间隔（TPOT）降至 5 ms 以内
工作与结束条件：达到目标结束
```

若要限时完成多负载目标，沿用第一个例子并调整以下条件：

```text
精度：固定 BF16
部署形态：比较聚合部署与预填充/解码分离
评测负载：输入长度 1024/8192 token、输出长度 128/512 token、并发 1/8 的组合
优化目标：每组负载的 P95 首 token 延迟降至 1 秒以内
工作与结束条件：在 12 小时内达到目标，达标或时间预算用尽时汇总结果
```
