# Qwen 吞吐与解码延迟优化

[English](qwen-decode.md) | 简体中文

```text
执行入口：当前 Foretoken 工作目录和任务指定的 Kubernetes context
历史实验：衔接已有 Qwen3.5-35B-A3B BF16 解码实验，核对负载与运行条件，复用可比结果并继续未解决的方向；没有记录时建立初始测量
模型：Qwen3.5-35B-A3B
精度：固定 BF16
部署形态：由 Agent 选择
单服务配置：由 Agent 根据测量选择 GPU 数、并行方式、CPU 核数和内存
可用资源：2*8 卡 MetaX C500；CPU 核数与内存按执行环境实际可用量确认并记录
最大并行实验数：由 Agent 根据可用资源和单实验需求确定上限，并写入实验说明
评测负载：每个服务分别测量并发 1 和 16，覆盖不同输入输出长度与自然回答；具体数据集和长度由 Agent 选择
优化目标：保持回答质量，提升单并发解码速度和 16 并发总输出吞吐（token/s），降低两组的解码延迟（TPOT）；分别报告相对原方案的变化与取舍
可改动范围：不限
工作与结束条件：采用任务发起时指定的总工作时长或性能目标
交付结果：完整迭代过程，记录每轮动机、方案与改动、测量结果、分析、耗时和下一步决定；汇总各组收益、保留方案、代码改动与结果链接
```

执行与资源安排见[优化任务](README_zh.md#自主执行)，记录方法见[实验记录手册](../experiment-records_zh.md)。
