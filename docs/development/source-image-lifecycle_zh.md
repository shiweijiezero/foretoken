# 源码部署生命周期

[English](source-image-lifecycle.md) | 简体中文

安装、部署和并行候选的命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。

## 安装与部署

平台安装负责共享控制器、CRD 和默认运行环境。部署从选定的代码目录构建前端及模型服务，只应用到本次提交的服务。两者分开，才能避免一个候选改变其他候选使用的平台。

CLI 按代码目录记录引擎目录选择，并在准备构建时同步源码删除。已删除的引擎文件不能从基础镜像重新出现。构建结果需兼容选定的 Python 和设备库。

## 并行构建

同一代码目录的源码准备和服务提交串行执行，其他目录可同时构建；平台安装、卸载与这些操作互斥。等待服务就绪前释放源码操作锁，使删除操作能够为尚未调度的服务腾出设备。

编译缓存用于加速构建，运行服务使用已发布的应用文件。每个候选保留独立的可写源码和导出目录；复用输出前，先停止仍可能读写这些文件的遗留发布任务。

## 构建与发布应用

Rust 可执行文件、Python 适配文件和推理引擎文件分别依赖各自的构建输入。重建受改动影响的产物，其余文件从与先前输入和运行环境一致的已完成应用中复用。更新时整体替换对应部分，包含文件删除；前一次构建或发布未完成时，按当前输入构建完整应用。

完整应用发布后，才提交给服务使用。每份应用包含运行所需的全部文件，不依赖编译缓存或被复用应用继续存在。

## 运行与清理

环境镜像和完整应用文件通过可信应用源的不可变清单一起发布。控制器先解析并保存选择，再创建工作负载，使模型准备、推理、重启和扩缩容始终使用同一份代码，而不依赖重新读取清单。部署成功要求选定代码和服务路由均已就绪；滚动更新与请求排空仍由控制器负责。

应用存储归平台管理，清理时保留部署、构建或回滚仍需使用的文件。源码清理须保留可恢复的构建输入，等其他使用者退出后再释放共享资源。卸载保留模型数据与输入归档。
