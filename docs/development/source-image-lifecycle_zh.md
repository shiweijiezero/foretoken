# 运行时源码生命周期

[English](source-image-lifecycle.md) | 简体中文

源码更新将运行时代码与提供依赖的镜像分开管理。本文说明维护这条路径时需要遵守的职责与生效规则。安装和重新部署命令见[从源码部署 Foretoken](../custom-deployment_zh.md)。

## 准备与发布

CLI 负责工作站上的源码目录绑定、安装设置保存、输入比较和产物准备。绑定对应实际集群和已安装的平台，不在工作站之间共享。同一工作站对同一集群的源码操作串行执行，避免准备和清理过程删除另一个操作正在使用的产物。

Foretoken 前端和 vLLM model-server 的 Rust 改动通过已有 Docker 构建器与编译缓存导出可执行文件；Python 适配代码则替换整个目录。仅更新 Python 时，保留该组件上次编译的可执行文件。准备完成后，确认源码目录在此期间没有变化，才保存输入快照作为后续比较依据。

代码包包含某个组件版本所需的完整可执行文件和适配代码。CLI 先上传到持久运行时存储的临时目录，完整发布后才在服务上选择该版本。发布后的目录不可修改。上传由独立的 CPU Pod 完成，旧推理进程无法启动时仍可发布新代码。

## 工作负载生效

CLI 在服务上选择源码版本，已有控制器负责前端滚动更新和模型 Pool/Group 替换。模型准备与推理进程必须收到相同的源码选择。启动时，镜像内的引导代码选择可执行文件和 Python 适配代码。代码包声明的可执行文件缺失时，启动失败，不会静默使用镜像中的旧代码。

CLI 检查当前选中的服务工作负载及其实际启用的源码，再报告部署成功。旧工作负载处于 Ready 状态不能证明更新已生效。源码未变化时复用已准备的产物；工作负载配置未变化时不触发替换。

## 镜像更新

引导代码在源码启用前执行，因此修改引导代码需要更新镜像。依赖、构建、控制面和 Helm 的改动也使用已有的平台安装流程。运行时存储不可用，或单节点可写存储卷尚待首次放置时，部署改用镜像；存储的首次节点放置仍由模型准备流程负责。

镜像准备以已部署的镜像引用和本次分发目的地判断是否可以复用。源码安装成功后，清除已有服务的源码选择，使工作负载使用新构建的镜像。保存的绑定不再引用本地快照或代码包时，CLI 会清理它们；卸载会删除工作站绑定，保留远端模型数据。

vLLM 本体的 Python/CUDA 代码与 vLLM-Omni 仍通过各自的推理引擎镜像构建流程更新，不属于运行时适配代码包。操作入口见[使用自定义推理引擎](../custom-deployment_zh.md#7-使用自定义推理引擎)。
