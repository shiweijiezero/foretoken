# 源码部署生命周期

[English](source-deployment.md) | 简体中文

本文说明维护源码部署功能时应保持的行为。安装、部署和并行实验的命令见[从源码部署 Foretoken](../deployment/source_zh.md)。

## 安装与更新

平台安装负责共享 CRD、依赖和默认运行环境，并准备初始应用构建。管理员可以单独准备命名空间的控制器、访问权限和默认应用，无需重新安装平台；成员随后使用这些应用提交服务配置。

源码部署从选定目录构建控制器、前端和模型服务，只更新目标命名空间。管理员准备的命名空间需要显式请求源码更新，并保留相应管理权限；普通服务操作不进入平台构建和清理。CRD 变更仍通过平台安装应用。

源码更新复用兼容的运行环境，依赖或基础镜像输入变化时自动重建。CLI 为每个 Foretoken 源码目录分别记住引擎目录。引擎源码需与选定的 Python、PyTorch 和设备库兼容。

例如，只更新前端代码时，未改动的模型实例继续提供服务。重复部署相同配置时复用已有控制器和应用；实际配置出现偏差时仍需修复。

## 构建与发布

Go 控制器、Rust 服务程序、Python 适配文件和推理引擎文件分别依赖各自的构建输入。只重建受改动影响的部分，整体替换对应产物，包含文件删除。其余文件从与先前输入和运行环境一致的已完成应用中复用。完整应用发布后再更新服务；运行中的服务不依赖可写的编译缓存。

编译缓存可在构建器重建后复用。构建在节点本地存储上执行，已完成的产物可存入指定存储类。源码工作区统一回收不再使用的产物卷和本地执行卷，应用和模型存储分别管理。

独立源码目录可以并行构建。同一源码工作区内的更新串行执行，服务变更在目标命名空间内串行提交；平台安装、卸载与源码更新互斥。获取锁的等待有时限，已经执行的持锁操作保留所有权。暂停和删除使更早的待提交操作失效；源码构建和就绪等待不持有命名空间的变更锁。

## 就绪与失败

选定的应用和服务路由均就绪后，部署才成功。滚动更新和请求排空由控制器管理，前端使用选定的运行缓存启动。服务状态和代码生效检查共用一个就绪截止时间，源码编译单独执行。

模型配置中的 `spec.timeouts.startup` 分别约束准备和服务启动。准备失败后，即使正在重试，也保留失败状态直到准备成功。配置被拒绝时应报告目标失败；服务容器重启则可在启动时限内继续恢复。

## 清理

构建失败或取消时，先停止构建器和发布任务，再复用编译输出；编译缓存保留供重试。清理使用独立时限，在就绪等待超时后仍可释放锁和资源。报告清理错误时应保留原始失败原因。

保留部署、构建或回滚仍需使用的应用，释放闲置资源前保存可恢复的构建输入。

`foretoken delete` 等待所提交的服务和工作负载完成清理。管理员准备的命名空间继续保留控制器和提供的存储，由管理员单独移除；自行管理的部署则移除不再使用的控制器，最后删除清单中声明的命名空间。源码清理回收闲置构建资源，保留源码目录、实验结果和源码归档。管理员卸载命名空间控制器时，也回收该命名空间不再使用的构建资源。

部署全部删除后再卸载共享平台，先回收编译卷，再移除供卷组件。模型数据和输入归档保留。
