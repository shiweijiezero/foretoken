# 源码部署生命周期

[English](source-deployment.md) | 简体中文

本文说明源码部署应保持的职责与生命周期。安装、部署和并行实验的命令见[从源码部署 Foretoken](../deployment/source_zh.md)。

## 安装与更新

平台安装负责共享 CRD、依赖、默认运行环境和部署管理器。源码安装还会准备初始应用，并发布开发工作站使用的构建设置。用户操作权限由管理员通过命名空间内的 RoleBinding 分配，安装本身不为用户授权。

CLI 为每个具名实例提交一个 `InferenceDeployment`。平台管理器从已安装的模板选择该实例的控制器，并准备控制器权限、已授权的目录绑定和 Gateway 访问。各控制器只调谐自己的实例，因此同一命名空间中的相邻实例可以运行不同的控制器代码。旧的命名空间级控制器退出后，实例控制器才能在该命名空间接管服务。

源码开发通过 `deploy -e` 或引擎源码选择显式启用，只构建选定 checkout 的控制器、前端和模型服务应用，更新目标实例。普通部署使用已安装的应用，不进入源码构建。CRD 和共享平台配置的变更仍通过平台安装应用。

新工作站从已安装的源码版平台读取构建设置，不需要重新安装平台。源码更新复用兼容运行环境，依赖或基础镜像输入变化时才重建。各 checkout 分别保存引擎源码选择；引擎需与选定的 Python、PyTorch 和设备环境匹配。

只更新前端代码时，未改动的模型实例继续提供服务。重复部署相同配置时复用已有控制器和应用，实际配置偏差仍需修复。新的平台默认值由显式部署选择，不因已有实例重启而自动切换。

## 构建与发布

Go 控制器、Rust 服务程序、Python 适配文件和推理引擎文件分别依赖各自的构建输入。只重建受改动影响的部分，整体替换对应产物，包含文件删除。其余文件从与先前输入和运行环境一致的已完成应用中复用。完整应用发布后再更新服务；运行中的服务不依赖可写的编译缓存。

编译缓存可在构建器重建后复用。构建在节点本地存储上执行，已完成的产物可存入指定存储类。源码工作区统一回收不再使用的产物卷和本地执行卷，应用和模型存储分别管理。

独立源码目录可以并行构建。同一 checkout 的源码更新和同一部署实例的服务变更分别串行执行。共享工作站状态目录的源码操作通过既有锁协调平台变更与构建；平台卸载期间，部署管理器拒绝启动新实例。获取锁的等待有时限，正在执行的持锁操作保留所有权。暂停和删除使更早的待提交操作失效；源码构建和就绪等待不持有实例的变更锁。

## 就绪与失败

选定的应用和服务路由均就绪后，部署才成功。滚动更新和请求排空由控制器管理，前端使用选定的运行缓存启动。服务状态和代码生效检查共用一个就绪截止时间，源码编译单独执行。

模型配置中的 `spec.timeouts.startup` 分别约束准备和服务启动。准备失败后，即使正在重试，也保留失败状态直到准备成功。配置被拒绝时应报告目标失败；服务容器重启则可在启动时限内继续恢复。

## 清理

构建失败或取消时，先停止构建器和发布任务，再复用编译输出；编译缓存保留供重试。清理使用独立时限，在就绪等待超时后仍可释放锁和资源。报告清理错误时应保留原始失败原因。

保留部署、构建或回滚仍需使用的应用，释放闲置资源前保存可恢复的构建输入。

`foretoken delete` 等待选中实例的服务、工作负载和模型引用退出后，平台才移除该实例的控制器及资源。其他实例、Kubernetes 命名空间和管理员提供的存储保留；动态缓存按配置的保留策略清理。源码清理回收闲置构建资源，保留源码目录、实验结果和源码归档。

部署实例全部删除后再卸载共享平台，先回收托管编译卷，再移除供卷组件。模型下载的回收遵循独立的[运行时缓存生命周期](runtime-cache_zh.md)。
