# 运行配置的职责归属

[English](runtime-configuration.md) | 简体中文

修改默认值、运行时派生值或多个模块共用的监听地址时，先确定它的解析与资源归属。模型部署的配置方法见[推理参数](../features/inference-parameters_zh.md)和[模型存储](../features/model-storage_zh.md)。

## 在所属边界解析，向下传递结果

例如，`kvCache.offload.cpuCacheSize: 0.5Gi` 表达用户需要的容量。模型编译器将它解析为 Kubernetes quantity，共用转换逻辑确认其精确容量为 `536870912` bytes。Pool 通过 Kubernetes 原生编解码保留现有数量字段格式；创建 Group 时消费已解析的数量，向引擎传递字节数，不再重新解析字符串。

模型标识和路径也遵循同样的规则。编译器统一补齐 tokenizer 和来源 revision；各引擎适配器只编译自身的并行方式与原生参数，Group 和前端目录使用已经规范化的模型标识。工作负载投射负责选定模型根目录，运行时保留这个结果，不再重新约定子目录名称。

| 职责 | 负责模块 | 消费方 |
| --- | --- | --- |
| 安装默认值与共享依赖绑定 | 平台 Chart 和安装流程 | 命名空间控制器配置 |
| 模型标识、容量单位与 Pool 覆盖规则 | 模型编译器 | Pool 解析与前端模型目录 |
| EC、P/D 和外部 Store profile 校验 | 共用运行配置 | 控制器启动与 Group 解析 |
| 模型启动、排空预算转换 | 共用生命周期编译 | vLLM、Omni 启动配置 |
| 挂载后的模型与缓存路径 | 工作负载投射 | 模型准备、服务运行和缓存恢复 |
| 引擎拓扑与原生参数 | 对应引擎适配器 | 引擎进程 |

消费方可以校验收到的契约，但不再补另一套默认值或重复领域转换。语义不同的预算仍应分开：要求整秒的 Kubernetes 字段和向上取整的引擎启动预算，不能仅因单位相同就合并。

## 按网络空间管理端口

模型 HTTP 端口变化时，容器监听、Service、探针、访问规则和公布地址需要一起更新。它们使用同一份运行端口，或引用 Kubernetes 命名端口。控制器的指标与健康检查、应用文件服务则各有自己的 Chart 内部定义；多个独立服务使用 `8080` 不代表它们应共用一个配置项。

model-server 在启动引擎前统一解析内部端口布局。它先考虑已经声明的 HTTP、缓存观测端口，以及本次启用的 P/D、ModelExpress 绑定，再选择不重叠的握手、分布式启动、校准和 KV 观测端口区间。数据并行端点需要为整个 rank 区间留出空间，而不只是检查起始端口。

同一执行组的成员根据相同配置得到相同布局。引擎参数、事件订阅、缓存查询和校准进程都消费这份结果。布局协调已知监听地址，真实 socket 仍由各监听方绑定；上游引擎内部动态分配的端口继续由上游管理。

本地临时服务使用另一种生命周期：性能剖析查看器绑定端口 `0`，保留取得的 listener，再公布实际地址；NodePort 由 Kubernetes Service 分配。复用这些已有资源归属，不另建一个先探测端口、关闭 socket、再尝试复用该数字的公共设施。

## 恢复时保留资源归属

持久运行缓存不可用时，只有该缓存根目录下的路径迁移到 Pod 临时缓存。独立挂载的模型目录继续使用投射时选定的位置。一次启动尝试中的模型准备、缓存复用和引擎启动必须使用同一份解析结果。

新增配置应沿其现有职责贯通创建、使用、观测和清理。替换表示方式时同步迁移消费者，通过控制面 Makefile 重新生成派生产物，并删除旧的解析与推导路径。安装默认值不会静默改写已有执行组；新配置何时生效见[源码部署生命周期](source-deployment_zh.md)。
