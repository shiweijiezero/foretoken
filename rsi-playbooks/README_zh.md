# RSI Playbooks

[English](README.md) | 简体中文

Foretoken 是一个面向 RSI（Recursive Self-Improvement，递归自提升）的推理基础设施框架，支持 Agent 自主修改、部署、评测和优化推理系统。

这套手册提供任务指导、实验方法与可复用经验，并持续吸收经过验证的发现，帮助后续迭代更有效地开展优化。

## 开始优化任务

克隆仓库：

```bash
git clone https://github.com/shiweijiezero/foretoken.git
cd foretoken
```

### Claude Code

在仓库目录启动一个专用于 RSI 的交互会话：

```bash
CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 claude
```

该命令仅在本次会话启用 Agent Teams。在此会话或已启用 Team 的会话中粘贴以下指令；自定义任务只需替换文件路径：

```text
/goal 使用 RSI skill 和 Agent Team，按照 rsi-playbooks/tasks/qwen-decode_zh.md 完成推理系统优化并交付规定结果。先阅读任务、已有实验记录和 rsi-playbooks/guidance/ 中的相关指导。使用任务分支，为并行写入安排独立 checkout。主 Agent 构思方向、分配资源、协调共享环境变更，负责集成和最终验收。给 Worker 完整研究问题及相关证据，为每个候选指定唯一执行负责人、明确资源和对照条件；该负责人在任务范围内连续迭代，不逐条等待命令。运行期间保持源码不变，恢复时核对已有作业与资源分配，随新发现持续协作。执行期间维持任务规定的有效工作人数，及时处理结果和成员的新任务请求。遵守任务的资源、时间预算和结束条件，用户要求暂停或停止时停止推进并完成必要收尾。
```

主 Agent 用同一个 goal 管理整体目标和团队推进，成员按各自职责协作。暂停时，用 `/goal clear` 结束自动续轮，再要求团队停止本任务的实验和采集进程。

## Agent 分工

团队以多个 Worker 并行推进优化方向，其他角色围绕它们协作。主 Agent 按任务资源和并行要求配置人数，保留成员上下文以承接后续工作：

| 角色 | 职责与数量 |
| --- | --- |
| 主 Agent | 构思方向、分配问题与资源、选择保留方案，协调共享环境变更和执行负责人；亲读保留代码，负责集成验证与最终交付。 |
| Advisor | 至少两名成员专注研究、瓶颈分析、探索、反馈和反思，熟悉代码与系统，搜索社区寻找灵感，用更广泛的证据质疑局部假设。主 Agent 在预算和运行环境上限内安排人数。 |
| Worker | 研究、实现和分析分配的问题，获派明确执行配额时运行候选。至少一名 Worker 跟进端到端路径；主 Agent 按有价值的独立工作安排人数。 |
| Experimenter | 构建并评测就绪候选，观察资源使用、记录执行事实并清理所分配资源；按评测容量安排人数，指定一名作者维护总览与报告。结论由未参与该候选的成员独立复核。 |

成员使用角色加编号或代号命名，例如 `lead-01`、`advisor-01`、`worker-01`、`experimenter-01` 或 `worker-alpha`。续派沿用稳定名称，具体职责写在任务中。具体命名与派工方式见[共用 skill](../.agents/skills/rsi/SKILL_zh.md#组建团队与派工)。

工作人数包含实际执行任务的 Worker、Experimenter 和 Advisor，按成员去重。主 Agent 不计入，等待、阻塞和已完成成员不算正在工作，兼任角色不增加人数。主 Agent 按任务要求和运行环境上限安排有效工作，处理人数不足的原因。

给每名 Worker 完整的问题、参考证据、范围与预算，按[角色协作约定](../.agents/skills/rsi/roles/common_zh.md)明确执行边界和资源交接。获派执行资源的 Worker 可在范围内连续迭代，主 Agent 处理共享变更与跨方向决策；Experimenter 直接返回结果，Advisor 贡献研究，也可独立复核自己未实现或执行的候选。主 Agent 审查保留改动，负责集成验证和交付。

成员及时交流会影响他人的发现，分配任务完成或无法推进时请求后续安排。指定 Experimenter 负责总览，各执行者维护分配的迭代记录，链接原始证据而非重复抄写。恢复时沿用原预算，核对记录与实际结果、进程状态，并补建缺失成员。

### 候选准备与评测并发

Worker 准备源码版本和对照，Experimenter 在所分配资源内承接就绪候选。从同一份任务记录分别统计准备中、等待评测和执行中的候选数量，准备并发与评测并发不必相同。评测资源经常等待时，适当提前准备有价值的候选；就绪队列积压时，减少新准备，优先分析结果或研究更有价值的替代路径。交接与积压调整见[角色约定](../.agents/skills/rsi/roles/common_zh.md#分开候选准备与评测)。

小任务可由同一成员兼任开发与执行；较大并行任务由 Experimenter 合并实验执行、资源观测和事实记录，独立复核作为另一项分工，不再要求常驻的记录或监控角色。

### 并行工作区

使用任务分支，为并行写入者提供独立 checkout，例如分别 clone。同一目录的不同分支不能隔离同时进行的修改。主 Agent 协调源码基线、写入者和执行分配，每个候选负责人使用独立部署身份、可写缓存和结果路径。构建和测量期间保持源码不变，释放工作区前保存改动与证据。

复用 Kubernetes 资源控制、sweep、benchmark 记录和 harness 任务通知，不另建 RSI 调度器。这些能力负责放置负载、执行确定的测量序列和保存运行事实，主 Agent 仍需协调共享资源争用与无竞争对照窗口。namespace 分离不保证性能隔离，具体执行方式见[共用 skill](../.agents/skills/rsi/SKILL_zh.md#隔离候选工作区与执行)。

## 设计目标

- 快速部署：将代码改动快速更新到目标集群中的推理服务。
- 测试与反馈：验证性能、模型质量和资源开销，了解改动效果。
- 观测与诊断：结合日志、指标和性能剖析，定位运行问题与性能瓶颈。
- 实验记录：关联每轮改动、运行配置、结果和决策，方便比较与复现。
- 参考与经验积累：查找、补充参考资料，将实验经验整理为可复用的指导。
- 行为与归因检查：检查模型实际行为，识别指标投机，判断收益是否确实来自预期改动。

## 使用步骤

一个研究问题可以包含多轮候选迭代，也可以以有依据的“不适用”结论结束。一轮迭代评估一个候选，其负载分组和重复测量属于同一轮。整个优化任务是否完成，仍由目标、预算和结束条件决定。

1. 明确要改善的行为、范围和判断标准。阅读相关代码、研究与历史结果，选择值得深入的问题。
2. Advisor 和 Worker 根据研究与已有证据提出假设；主 Agent 选择对照，在投入较大工作前确认执行可行性。
3. Worker 实现并解释候选与对照，指定执行负责人在约定范围内按[源码部署流程](../docs/custom-deployment_zh.md)构建部署，确认预期路径实际执行。
4. 执行负责人运行选定的[评测](../benchmarks/README_zh.md)，确定的测量组合使用现有[参数扫描](../benchmarks/docs/recipes_zh.md)，保持对照条件稳定。Worker 分析输出、日志和 profile，与 Advisor 交流，在分配范围内继续推进。
5. 由未参与该候选实现和执行的成员阅读代码与原始结果，检查模型行为、对照条件和收益归因。处理审查问题的同时推进不受影响的准备工作，按[实验记录手册](experiment-records_zh.md)保存证据与结论。
6. 依据证据修订或放弃实验候选，主 Agent 亲读保留改动及相关调用路径，结合独立审查安排组合服务验证。将可复用发现沉淀到指导中，在剩余预算内选择下一项研究问题。

## 选择评测

按本轮优化目标选择评测。命令选择和记录参数见[实验记录手册](experiment-records_zh.md)。

| 评测目的 | 工具与命令 | 查看内容 |
| --- | --- | --- |
| 比较延迟、解码速度和吞吐 | [性能评测](../benchmarks/docs/perf/README_zh.md)，`foretoken perf` | 成功数、延迟分布、TPOT、吞吐及实际输出长度 |
| 评估回答质量 | [质量评测](../benchmarks/docs/eval/README_zh.md)，`foretoken eval` | 得分、样本数、评分方式和逐题回答 |
| 定位计算、通信和等待开销 | [性能剖析](../benchmarks/docs/profile/README_zh.md)，`foretoken perf --profile` | 执行时间线；速度对比另用不带剖析的运行 |
| 比较不同并发、输入长度和流量下的表现 | [参数扫描与负载配置](../benchmarks/docs/recipes_zh.md) | 各负载点的指标及变化趋势 |

命令选项可用 `foretoken perf --help` 和 `foretoken eval --help` 查询。
