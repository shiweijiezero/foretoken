Use this as the task overview. Link the task specification, experiment directory, original start and deadline, and generated results. Keep this overview across resumptions. See the [report workflow](../experiment-records.md#maintain-the-user-facing-report).

## Objective

Describe the model, workloads, target outcome and fixed constraints. Identify the original reference configuration and the current validated configuration for each applicable scope. Link their actual code, deployment and measured run evidence.

## Results

[Measured comparisons, retained versions and search history](figures/progress/progress-summary.md)

The linked view is generated by `foretoken plot --progress EXPERIMENT_DIR` from the iteration owners' selected runs and judgments. Each scope first lists measured retained branch tips and their run/configuration/source links, followed by rejected and failed approaches, repeat statistics, original-reference changes and measured parents. Experimenters update their own records and refresh this shared view directly; there is no numerical table to maintain in this overview.

## Mechanisms and open questions

Link each approach's `iterations/<name>/notes/iteration.md`. Those notes own the hypothesis, implementation, interpretation, independent review and next step. Explain a cross-approach conclusion here only when it needs its own synthesis; do not repeat each iteration's numbers and status.

A and B independently measured from P remain separate configurations. Name a combination only after it has actually run, and keep retention limited to the measured scope. Continue development from the applicable validated configuration; the original baseline remains a reference.

## Pause or completion

Record the reason, final outcome, unfinished validation and links to actual resource cleanup. Deliver the same overview and generated result view. Use the task's requested delivery location; adjust links from this file's actual directory.
