# 06｜评估研究机会

[English](06-opportunity-assessment.md) | 简体中文

结合已有源码分析和实验记录，比较一个方向的收益空间与所需投入。Observer 评估当前证据和时间使用，主 Agent 决定方向、负责人和预算。评估与决定分别写入已有巡查笔记和团队记录。

巡查时只更新变化的条目，复用仍适用的证据与判断。评分不要求新增实验或质量评测；只有改动可能影响输出且已有证据不足时，才按任务约定的频率安排质量验证。

## 从具体比较开始

按研究问题归并测量，候选的机制、收益或成本有实质差异时再单列。注明负载、参照、候选版本、当前阶段、原件链接，以及负责人已经记录的剩余工作估计。缺失值记为 `U`（未知），不适用记为 `N/A`。缺少的估计或决定由 Observer 提醒主 Agent。

例如，以下虚构估计采用同一吞吐负载、共同 baseline、相同服务验证里程碑，剩余墙钟 8 小时。仅为演示，假设其他资源成本相同且均在预算内。

| 方向 | 估计收益 | 新增小时 | 判断 |
| --- | ---: | ---: | --- |
| A：小 kernel 改动 | 1–3% | 0.3–0.4 | 上限低；未被其他行支配 |
| B：执行机制改造 | 12–18% | 1.6–2.4 | 潜力与成本更高，证据仍来自局部 |
| C：相似参数继续扫描 | 0–1% | 3–4 | 给定估计下被 A 支配 |
| D：尚未弄清的新思路 | U | U | 信息不全，支配关系待定 |

A 与 B 有不同取舍，前沿不能选择下一任务。B 的预期不是已测服务收益。另一个环境修复若花 0.8 小时、在三个剩余运行中各省 0.5 小时，预计净节省 0.7 小时，计为准备收益。

## 区分实测与研究机会

实测部署前沿在任务正确性与质量要求下比较已测性能和资源消耗。仍适用的历史证据可以支持这些要求，无需每次测速后重新评分。尚未明确的输出影响与速度结果一起记录，暂不当作已确认的部署收益。

研究机会前沿比较已记录方向的预期收益与新增成本。保留任务原始 baseline，同一比较采用共同参照和指标定义，硬件或协议不兼容时分组。相对原型的剩余收益与相对共同参照的总收益分开。多个必需负载保留收益向量，避免改善遮住回退；只有任务指定权重时才汇总。

估计注明作者、时间、假设、来源与范围。区分实测波动、统计区间和工程上下界；测量区间重叠时，仅凭均值不能确认改善。

## 描述收益、证据与成本

先列原始数值，再用以下 0–4 分概括。分数用于讨论，不是概率或采用门槛；数值跨档时给出分数范围。同一任务沿用相同尺度；主 Agent 调整尺度时，先说明原因，再统一比较重新评分的条目。

### 收益与上限：G

吞吐提升为 `100 × (候选 / 参照 − 1)`%，延迟下降为 `100 × (1 − 候选 / 参照)`%。保留负值、输出长度与波动，实测和预测分别标识。只有理想上限时，不能据此填预期值或下界。

| G | 每项必需指标的收益 |
| --- | --- |
| 0 | 零或负值，保留实际带符号数值 |
| 1 | 大于 0%、小于 5% |
| 2 | 至少 5%、小于 10% |
| 3 | 至少 10%、小于 20% |
| 4 | 至少 20% |

根据相关关键路径估算上限。组件占总耗时比例为 `f`，局部加速倍数为 `s`，新增开销占原耗时比例为 `a` 时，简化加速比为 `S = 1 / (1 − f + f/s + a)`。固定工作量下，吞吐提升为 `100 × (S − 1)`%，耗时下降为 `100 × (1 − 1/S)`%。完全消除占总耗时 4% 的组件，吞吐最多提升 4.17%；该组件加速 2 倍，整体提升 2.04%。重叠的 GPU kernel 时间不能累加成 `f`，延迟节省也不必然成为服务吞吐提升。

### 可行性 F、证据 E 与信息 I

F 评估机制在任务语义、精度、硬件和资源约束下的可行性，与环境就绪程度分开。E 支持某项明确结论：证据充分的负结果可以是 E4、G0。I 描述本观察期实际获得的信息，与负责人预期的未来信息价值分开。

| 分数 | F：机制可行性 | E：所述结论的证据 | I：已获得的信息 |
| --- | --- | --- | --- |
| 0 | 违反必要不变量或已证上限 | 尚无支撑证据 | 重复已知事实 |
| 1 | 机制已描述，关键假设未解决 | 理论、源码或其他条件的结果 | 复现症状或核对就绪状态 |
| 2 | 分析支持路径，仍有集成假设 | 局部对照或组件测量 | 区分一个解释或建立有用上限 |
| 3 | 在任务约束内核算了依赖与新增成本 | 匹配服务对照，复现或覆盖尚不完整 | 解决关键因果或正确性问题 |
| 4 | 代表性执行验证机制与必要不变量 | 重复且有代表性的对照支持所述范围 | 经独立检查并在相关场景复用的发现 |

链接证据、适用范围和未解假设。原型 bug 不证明整类机制不可行，组件结果也不代表服务表现。E 包括已有且仍适用的正确性证据。代码量、消息和 PR 数量不代表 I。

### 新增成本：C

已付成本用于反思，新增成本用于决策。记录墙钟小时、实际归属本任务的 GPU 小时和 Agent 工作小时；证据允许时分开准备与等待。并行墙钟不能相加，开放回合也不等于已测有效工作。token 或金额成本需有可靠归属。

成本比较采用相同证据里程碑。组件探针与完整服务验证产出不同；近期里程碑只是探针时，也说明到任务级验证的剩余成本。

对应资源的剩余预算 `B > 0` 时，按新增成本 `c` 的比例 `r = c/B` 给分。预算已用尽时，正的新增成本为 C0，无新增成本为 C4。同一快照各行采用相同时间与预算。跨轮保留原始成本：预算缩小可以使 C 降低，但不说明方法本身变得低效。

| C（越高表示成本越小） | 占剩余预算的比例 |
| --- | --- |
| 4 | `0 ≤ r ≤ 0.05` |
| 3 | `0.05 < r ≤ 0.15` |
| 2 | `0.15 < r ≤ 0.35` |
| 1 | `0.35 < r ≤ 1` |
| 0 | `r > 1` |

有预算时分别给出 `C_time`、`C_gpu`、`C_agent`；无预算则保留原始成本，C 记 `U`。墙钟预算截止于任务期限，GPU 与 Agent 预算采用实际可用额度。未知成本为 U，与已知超预算的 C0 分开。

## 单独评估环境工作

环境工作只有实测推理性能变化才填写推理 G。其赋能价值记为 `U_env`：0，没有已记录消费者；1，便利性或未证实的延误改善；2，实测准备时间节省；3，解除已记录实验的真实阻塞；4，经验证的修复解锁多个实验或防止已复现的反复故障。

净累计准备时间节省估计为 `N × 每次节省 − 剩余修复及验证时间`，N 只计剩余任务内可能执行的次数，计入部署成本。节省位于串行关键路径时才等于任务墙钟节省，准备重叠时结合排期估算。GPU 与 Agent 成本另列。修复使原本不能执行的实验变得可行时，直接指出该实验，不虚构节省分钟数。同一项推理收益只归因一次。

Observer 报告本期和任务累计的时间分配、覆盖范围与被延误的工作。环境投入增加但就绪程度未改善时，提醒主 Agent 判断，不设置自动比例上限。

## 判断非支配机会

帕累托支配指所有比较目标都不差、至少一个严格更好。按主 Agent 确定的共同负载、里程碑和资源范围，比较原始收益向量与新增成本。F、E、I 随比较展示，不相加或相乘生成优先级或成功概率。

使用上下界时，只有 A 每项收益的下界都不低于 B 的上界，且 A 每项成本的上界都不高于 B 的下界，并有一项严格更好，才称 A 稳健支配 B。结论以所列上下界和假设为准；否则支配关系待定，未知值或不兼容条件也不能判支配。粗评分相同不代表原始数值相同。

已证实违反约束的方向保留反证，排除在可行前沿外；可行性未明时保留未知。除前沿归属外，还要展示绝对收益空间和时间分配，极便宜的 1% 改善也可能非支配。Observer 提醒主 Agent 注意低上限、回退、薄弱估计或不断增加的成本。主 Agent 解释选择、安排工作和预算、确定复核时机；后续巡查对照决定核查实际工作与证据。
