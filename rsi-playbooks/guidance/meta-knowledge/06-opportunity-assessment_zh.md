# 06｜帕累托引导探索（PGE）

[English](06-opportunity-assessment.md) | 简体中文

帕累托引导探索（Pareto-Guided Exploration，PGE）帮助团队优先攻克重要且有大幅改善潜力的问题，深入改造算法、算子、数据流和执行架构。主 Agent 选择主攻方向并安排持续投入，小改进与独立备选可以并行；Evaluator 根据证据评估进展、成本和收益，供主 Agent 调整研究安排。

## 先组织研究，再比较候选

先找出影响目标负载的主要限制，再研究哪些机制能够改变它们。Explorer 持续寻找新思路；主 Agent 选择主攻问题，为核心实现和关键实验安排时间。快速改进可以利用并行资源，研究优先级由问题的重要性和改善空间决定。

已有候选按收益和成本比较，新机制从问题、假说和关键未知开始研究。收益与集成成本可以随着源码分析和原型实现逐步明确。主 Agent 根据整条研究路线的潜力决定投入，为尚未验证的重要思路保留探索空间。

例如，可以这样描述处于不同阶段的研究问题：

| 研究问题 | 已有证据 | 关键未知 | 研究可能产生的信息 |
| --- | --- | --- | --- |
| 改变数据布局能否消除重复物化？ | 中间拷贝占据已观察路径的重要部分 | 下游能否直接消费新布局，而不引入转换成本 | 可运行的核心路径，以及节省与新增流量的解释 |
| 重组执行能否重叠当前暴露的阶段？ | Profile 存在等待与部分串行执行 | 哪些依赖是必要的，哪些来自当前实现 | 因果依赖模型与可执行的替代调度 |
| 改变推测机制能否降低每个接受 token 的成本？ | 已记录各负载的草稿与验证成本 | 改动能否减少总工作量，而非只提高接受率 | 解释或原型，澄清联合成本取舍 |

阶段成果可以是机制解释、重要限制或可运行的核心实现，服务收益在后续集成中验证。原型变慢或失败时，结合源码和测量查明原因，判断该完善实现还是重新考虑假说。

按研究问题与版本整理结果，注明负载、参照、阶段、原件和剩余工作估计。未知记 `U`，不适用记 `N/A`，每轮根据新证据更新。质量验证按输出影响和任务约定安排，保留方案满足任务的正确性、精度与资源要求。

## 区分实测与研究机会

实测部署前沿比较满足任务正确性与质量要求的方案，展示已测性能和资源消耗。复用仍适用的历史验证；输出影响尚待核实时，随速度结果注明进度。

研究机会前沿比较预期收益与后续投入。保留任务原始 baseline，同组采用共同参照和指标定义，硬件或协议不同的数据分别比较。列清相对当前原型的剩余空间，以及相对共同参照的总收益。多个必需负载逐项展示，任务指定权重时再计算汇总值。

估计注明作者、时间、假设、来源与范围，并说明范围来自复测波动、统计分析还是工程估算。解释收益时同时考虑这些不确定性。

## 描述收益、证据与成本

先列原始数值，再用 0–4 分概括，便于对照讨论。数值跨档时给出分数范围。同一任务沿用相同尺度；调整尺度时说明原因，并统一更新参与比较的条目。

### 收益与上限：G

吞吐提升为 `100 × (候选 / 参照 − 1)`%，延迟下降为 `100 × (1 − 候选 / 参照)`%。同时记录回退、输出长度和波动，分别标明实测值、预期收益和理想上限。

| G | 每项必需指标的收益 |
| --- | --- |
| 0 | 零或负值，保留实际带符号数值 |
| 1 | 大于 0%、小于 5% |
| 2 | 至少 5%、小于 10% |
| 3 | 至少 10%、小于 20% |
| 4 | 至少 20% |

根据相关关键路径估算上限。组件占总耗时比例为 `f`，局部加速倍数为 `s`，新增开销占原耗时比例为 `a` 时，简化加速比为 `S = 1 / (1 − f + f/s + a)`。固定工作量下，吞吐提升为 `100 × (S − 1)`%，耗时下降为 `100 × (1 − 1/S)`%。完全消除占总耗时 4% 的组件，吞吐最多提升 4.17%；该组件加速 2 倍，整体提升 2.04%。`f` 按关键路径上的实际耗时计算；服务吞吐的变化再用对应负载验证。

### 可行性 F、证据 E 与信息 I

F 评估机制在任务语义、精度、硬件和资源约束下的可行性，与环境就绪程度分开。E 支持某项明确结论：证据充分的负结果可以是 E4、G0。I 描述本观察期实际获得的信息，与负责人预期的未来信息价值分开。

| 分数 | F：机制可行性 | E：所述结论的证据 | I：已获得的信息 |
| --- | --- | --- | --- |
| 0 | 违反必要不变量或已证上限 | 尚无支撑证据 | 重复已知事实 |
| 1 | 机制已描述，关键假设未解决 | 理论、源码或其他条件的结果 | 复现症状或核对就绪状态 |
| 2 | 分析支持路径，仍有集成假设 | 局部对照或组件测量 | 区分一个解释或建立有用上限 |
| 3 | 在任务约束内核算了依赖与新增成本 | 匹配服务对照，复现或覆盖尚不完整 | 解决关键因果或正确性问题 |
| 4 | 代表性执行验证机制与必要不变量 | 重复且有代表性的对照支持所述范围 | 经独立检查并在相关场景复用的发现 |

每项分数链接证据、适用范围和未解假设。较低的 F 或 E 指出需要深入研究的问题；分析时同时考虑当前原型表现和新实现可能打开的空间。E 可复用已有的正确性证据，I 则依据实际澄清的问题评分。

### 新增成本：C

已付成本用于复盘，新增成本用于安排后续工作。分别记录实际经过的小时数、归属本任务的 GPU 小时和 Agent 工作小时，并说明准备、等待和并行时段。Agent 工作时间按实际活动统计；有可靠数据时补充 token 或金额成本。

比较成本时注明预期产出，例如组件分析、核心原型或完整服务验证。先估计下一研究阶段的投入，集成成本尚不明确时保留 U，随实现逐步更新。重要问题可以从这样的阶段性投入开始。

对应资源的剩余预算 `B > 0` 时，按新增成本 `c` 的比例 `r = c/B` 给分。预算已用尽时，正的新增成本为 C0，无新增成本为 C4。同一快照各行采用相同时间与预算。跨轮同时保留原始成本与剩余预算，以便解释 C 的变化。

| C（越高表示成本越小） | 占剩余预算的比例 |
| --- | --- |
| 4 | `0 ≤ r ≤ 0.05` |
| 3 | `0.05 < r ≤ 0.15` |
| 2 | `0.15 < r ≤ 0.35` |
| 1 | `0.35 < r ≤ 1` |
| 0 | `r > 1` |

有预算时分别给出 `C_time`、`C_gpu`、`C_agent`；无预算则保留原始成本，C 记 `U`。墙钟预算截止于任务期限，GPU 与 Agent 预算采用实际可用额度。未知成本用 U 表示，已知超预算用 C0 表示。

## 单独评估环境工作

环境工作的价值主要看它解锁了哪些实验、节省了多少准备时间；测到推理性能变化时再记录 G。用 `U_env` 概括其作用：0，没有已记录消费者；1，便利性或未证实的延误改善；2，实测准备时间节省；3，解除已记录实验的真实阻塞；4，经验证的修复解锁多个实验或防止已复现的反复故障。

净累计准备时间节省估计为 `N × 每次节省 − 剩余修复及验证时间`，N 只计剩余任务内可能执行的次数，计入部署成本。节省位于串行关键路径时才等于任务墙钟节省，准备重叠时结合排期估算。GPU 与 Agent 成本另列。修复解除了执行阻塞时，注明受益的实验及其研究价值。

Evaluator 结合本期和累计投入，报告环境准备推进了哪些工作、还有哪些阻塞，以及对主攻研究的影响，供主 Agent 调整安排。

## 判断非支配机会

帕累托支配指所有比较目标都不差、至少一个严格更好。按主 Agent 确定的共同负载、里程碑和资源范围，比较原始收益向量与新增成本。F、E、I 随原始数值一起展示，帮助解释取舍。

使用上下界时，只有 A 每项收益的下界都不低于 B 的上界，且 A 每项成本的上界都不高于 B 的下界，并有一项严格更好，才称 A 稳健支配 B。用原始数值检验这些条件，并注明假设；证据不足时将支配关系标为待定。

例如，两条通向同一验证里程碑的实现路径使用共同参照：A 的收益范围为 4–6%、新增成本为 3–4 小时；B 为 8–10%、1–2 小时。给定这些假设，B 支配 A。机制有了新实现或新证据后，再更新比较。

在满足任务约束的候选中比较前沿，可行性尚未明确的思路继续记录其未知与研究进展。前沿上的方向各有取舍，主攻研究还要考虑问题的重要性和突破空间。Evaluator 核对重要机制是否有人持续研究、是否获得实现时间与实验机会，并报告被小改动、报告或环境工作挤占的情况。

主 Agent 据此选择或调整研究组合：主攻问题、独立备选、并行的小改进、负责人、阶段预算，以及预期认识或实现产出。重要问题保持连续投入，原型的阶段性失败或变慢交回负责人分析。方向调整依据问题的新认识、潜在收益与剩余工作价值。后续评估对照这些决定核查实际投入与进展。
