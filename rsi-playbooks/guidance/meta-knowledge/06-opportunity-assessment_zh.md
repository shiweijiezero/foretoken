# 06｜评估研究机会

[English](06-opportunity-assessment.md) | 简体中文

容易执行的实验可能只剩很小的收益空间；困难的实现可能潜力较大，但证据较弱。应分别比较这些维度，不能用完成实验数量或一个综合分代替判断。

Observer 根据源码、工作和运行记录评估当前方向，量化取舍并提醒主 Agent 哪些决定需要关注。主 Agent 选择未来方向、预算、负责人和复核点。评估写入已有巡查笔记，主 Agent 的回应写入已有团队记录。

## 明确比较对象

每个研究问题和候选版本一行，覆盖正在进行、等待、已准备的方向及已有记录中的备选思路。注明负载、参照、拟改变的机制、当前阶段，以及负责人已描述的下一证据里程碑。缺少里程碑时标为未知，不由 Observer 补派任务。每轮更新发生变化的行，保留之前判断的日期与依据。

区分两个前沿：

- 实测部署前沿：在可比负载和资源条件下完成评测，并满足任务正确性与质量要求的配置。使用实测吞吐、延迟、资源消耗等任务指标；缺少必要评测的配置尚不属于这个已验证集合。
- 研究机会前沿：依据现有方向的潜在收益与剩余成本估计进行比较，可行性和证据分数说明估计的支撑程度。位于这个前沿不代表已经取得可部署的改善。

同一配置的后续测量不替换任务的原始 baseline。每个收益注明使用的参照，协议或硬件变化另分组。同一前沿的方向使用共同参照配置与指标定义；相对原型的剩余收益单列，转换到共同参照后再比较机会。任务要求多个负载时保留收益向量：某个负载的大幅改善不能遮住另一个负载的回退。只有任务已经指定权重时才使用汇总指标。

## 先记数值，再给分数

每项估计注明作者、观察时间、来源、假设和范围。缺证据用 `U`，不适用用 `N/A`；未知不等于零。评分使用 0–4 整数，数值跨档时同时给出评分范围。分数用于描述，不是概率或采用门槛。同一任务沿用相同尺度；主 Agent 调整尺度时，说明原因并重新计算参与比较的行。

### 收益与上限：G

按负载和指标分别列出实测收益与预期剩余收益。吞吐提升为 `100 × (候选 / 参照 − 1)`%，延迟下降为 `100 × (1 − 候选 / 参照)`%。保留负值、输出长度和测量波动。原型当前变慢与未来预期收益分别记录；较高预期必须说明依赖哪项尚未完成的改动。

用关键路径开销估算上限。组件占相关总耗时的比例为 `f`，局部加速倍数为 `s`，新增开销占原耗时的比例为 `a` 时，简化加速比为 `S = 1 / (1 − f + f/s + a)`。固定工作量下的吞吐提升为 `100 × (S − 1)`%，耗时下降为 `100 × (1 − 1/S)`%。只用于测得的路径与所列假设；GPU kernel 时间可能重叠，其总和不能直接当 `f`，延迟估算也不能自动变成服务吞吐估算。

例如，一个组件占总耗时 4%，即使完全消除，理想加速上限也只有 4.17%，还未扣新增成本；把该组件加速 2 倍，整体只提升 2.04%。局部 kernel 数字很大，并不改变这个约束。

以下为逐指标使用的默认收益档位，主 Agent 可在比较前按任务设置其他尺度。生产规模下 1% 也可能有价值，档位不要求因此停止方向。

| G | 端到端收益或估计收益区间 |
| --- | --- |
| 0 | 零或负值，同时保留实际带符号数值 |
| 1 | 大于 0%、小于 5% |
| 2 | 至少 5%、小于 10% |
| 3 | 至少 10%、小于 20% |
| 4 | 至少 20% |

可实现收益估计与理想上限同时保留。只有上限时，不能据此填预期值或下界。实测和预测采用相同档位但分别标识，缺少某个负载的估计时，不能拿最好负载的数值代填。

### 理论可行性：F

F 评估拟采用机制在任务精度、语义、硬件和资源约束下是否成立，与当前环境是否准备好分开。

| F | 证据锚点 |
| --- | --- |
| 0 | 所述机制违反必要不变量，或被已证上限排除 |
| 1 | 已说明机制，但关键依赖或正确性论证尚未解决 |
| 2 | 源码或理论分析支持该路径，仍有主要集成假设 |
| 3 | 已核算关键路径、依赖和新增开销，在任务约束内有可行实现路径 |
| 4 | 代表性实现已验证机制和必要不变量，主要剩余不确定性在收益或适用范围 |

F1–F3 写明假设，F4 链接实际执行。当前原型有 bug 不证明整类思路不可行；论文有结果或代码有开关，也不证明本任务的实际路径已成立。

### 证据强度：E

E 表示所述收益或失败结论的证据强度，不表示方向成功的概率。反复证实的负结果可以是 E4、G0。注明支撑的是哪项结论，不能把组件结果的 E 分数套给未测的服务收益。

| E | 证据锚点 |
| --- | --- |
| 0 | 尚无支撑所述结论的证据 |
| 1 | 有理论推导、源码阅读或其他条件下的结果 |
| 2 | 有相关局部控制或组件测量，仍需外推到服务 |
| 3 | 匹配的服务对照覆盖所述条件和必要检查，但复现或更广覆盖尚不完整 |
| 4 | 重复且有代表性的对照支持所述范围内的结论、波动和必要正确性／质量 |

给出样本数、重复次数、观察范围和未解混杂。单次运行不能建立噪声范围或校准过的成功概率。不确定区间注明来源：复测最小／最大值、统计区间与工程估计并不是同一回事。

### 成本：C

分开已付成本和剩余成本。已付成本用于反思，未来机会比较只使用新增投入。记录墙钟小时、实际归属本任务的 GPU 小时和 Agent 工作小时，证据允许时单列等待与准备；并行墙钟不能相加，开放的 Agent 回合也不等于有效工作。只有运行环境提供可靠归属和价格时才补 token 或金额成本。

估计达到所列证据里程碑还需要的实现、环境准备、测量与分析成本。注明里程碑范围：十分钟组件探针不能被当成与完整服务验证相同的产出。近期里程碑仅为探针时，也列出走到任务级验证的剩余成本。

某项资源有明确剩余预算 `B` 时，用新增成本估计 `c` 的比例 `r = c/B` 给分。同一快照内各行使用相同的观察时间与预算，成本区间映射为评分区间。墙钟预算是距任务截止的时间；GPU／Agent 预算只采用明确可用的额度，不能把共享主机上繁忙的设备按理论最大容量计算。

| C（越高表示成本越小） | 占该资源剩余预算的比例 |
| --- | --- |
| 4 | `0 ≤ r ≤ 0.05` |
| 3 | `0.05 < r ≤ 0.15` |
| 2 | `0.15 < r ≤ 0.35` |
| 1 | `0.35 < r ≤ 1` |
| 0 | `r > 1` |

存在对应预算时分别给出 `C_time`、`C_gpu`、`C_agent`。没有某项预算就保留原始单位成本，归一化评分标 `U`。确定估时超出截止时间是 C0，尚未估时是 U；较小里程碑是否值得做，由主 Agent 判断。

### 信息收益：I

排除一个优化假设也可能有价值。对本观察时段实际获得的信息评分，与研究负责人描述的预期信息价值分开。

| I | 证据锚点 |
| --- | --- |
| 0 | 重复已知事实，没有减少已命名的不确定性 |
| 1 | 核对准备状态或复现症状，尚未区分竞争解释 |
| 2 | 区分一个已命名解释，或建立有用上限 |
| 3 | 通过有区分力的对照解决关键因果或正确性问题 |
| 4 | 建立经过独立检查、已在相关场景复用的机制或限制 |

链接研究前后的未知问题。代码量、新颖性声明、消息或 PR 数量不代表 I。高 I 可以说明已完成研究的价值，但不证明推理提速，也不自动支持无限追加投入。

## 环境工作与机会成本

除非实际测到了推理性能变化，环境工作不填写推理 G。另按解除的阻塞及对已确定实验的影响评估：

| 环境赋能分 U_env | 已证实的价值 |
| --- | --- |
| 0 | 没有已记录的消费者或当前依赖 |
| 1 | 改善便利性，或对已命名消费者的延误改善尚未证实 |
| 2 | 为可执行对照带来实测准备时间节省 |
| 3 | 解除某个已记录实验的真实阻塞 |
| 4 | 已验证的通用修复解锁多个已记录实验，或防止已复现的反复故障 |

净累计准备时间节省估计为 `N × 每次节省 − 剩余修复及验证时间`。`N` 取剩余任务内可能执行的次数，不算假想的未来项目。只有这些节省位于任务的串行关键路径时，才等于墙钟节省；准备工作重叠时应结合实际排期另算。使用范围、计入部署成本，GPU／Agent 成本另列。修复的价值若是使原本不能执行的实验变得可行，直接注明被阻塞的结果及其机会估计，不虚构节省分钟数。同一项模型收益不能同时归给环境修复和模型优化。

Observer 报告本观察时段和任务累计的环境、实现、测量、分析与等待占比，注明覆盖范围和哪些任务被延误。准备成本不断增加而就绪程度未变，或赋能证据薄弱时，应明确提醒。环境准备可能必要，价值取决于它让哪些工作成为可能，不设置自动比例上限。

## 判断非支配机会

帕累托支配指所有比较目标都不差、至少一个严格更好。主要机会比较使用原始收益向量与新增成本维度；主 Agent 在比较前确定负载集合、里程碑范围和资源维度。F、E、I 随前沿展示，说明依据，不把所有评分都加成目标导致每个方向都非支配。

不把序数分数相加或相乘生成优先级，也不把 `G × F × E / 成本` 当作期望收益。高确定性的小收益与证据较弱的大机会都可能值得考虑。缺失信息单独可见，不宣称它已进入完整可比集合。

使用上下界时，只有 A 在每项必要收益上的下界都不低于 B 的上界，且 A 在每项成本上的上界都不高于 B 的下界，并有一项严格更好，才称 A 在给定范围内稳健支配 B。这是基于所列假设的判断，不是统计保证。上述边界不等式不能证明支配时，关系待定；边界相接仍可能在其他维度严格更优。值未知或条件不兼容时不能证明支配。粗评分相同不代表原数值相同；声明支配时列出支配者和具体维度。

位于前沿不等于有很大潜力：极便宜的 1% 改善仍可能非支配。因此 Observer 同时指出绝对收益上限、回退、不确定性和实际时间分布。若投入集中在低上限方向，而已记录的高潜力问题没有推进，或环境投入增加却没有改变可执行工作，应提醒主 Agent 考虑这个取舍；具体如何调整由主 Agent 决定。

### 数值示例

以下为虚构估计：同一吞吐负载与共同参照配置、同一服务验证里程碑、剩余墙钟 8 小时。仅为演示，假设其他资源成本相同且均在任务限制内。

| 方向 | 估计收益 | G | F | E | 新增小时 | C_time | 已得 I | 评估 |
| --- | ---: | --- | ---: | ---: | ---: | --- | ---: | --- |
| A：小 kernel 改动 | 1–3% | 1 | 4 | 3 | 0.3–0.4 | 4 | 2 | 非支配，但绝对上限低 |
| B：执行机制改造 | 12–18% | 3 | 3 | 2 | 1.6–2.4 | 2 | 3 | 非支配，潜力与成本更高、证据较弱 |
| C：相似参数继续扫描 | 0–1% | 0–1 | 2 | 1 | 3–4 | 1 | 0 | 给定假设下被 A 稳健支配 |
| D：尚未弄清的新思路 | U | U | 1 | 0 | U | U | 0 | 评估不完整，不能判已被支配 |

A 与 B 说明前沿不能替主 Agent 选择任务。若 A 理想上限只有 3%，B 的估计又仅来自组件测量，两项限制都应展示，不能把 B 的估计宣传为实测。另一个环境修复若花 0.8 小时、在三个已记录运行中各省 0.5 小时，预计净累计准备时间节省为 0.7 小时，只有这些操作位于任务串行关键路径时才等于墙钟节省；这是准备收益，不是吞吐收益。

## Observer 交付与主 Agent 回应

每轮巡查在已有记录中维护紧凑评估表，覆盖已记录方向的来源、原数值、分数、不确定性、已付／剩余成本和前沿状态。概括与上轮相比的变化、哪些投入产生了新信息，以及哪些取舍或缺失估计需要主 Agent 关注。Observer 不选择下一机制、不定预算、不派工、不改变任务目标。

主 Agent 给出自己的目标与证据解释，明确继续、修改或停止哪个方向，指定负责人和新增预算、预期可观察结果，以及再次考虑的时间或证据条件。选择被支配或低上限方向时说明理由，例如它是必要前置条件。下一轮 Observer 对照这些决定核查实际工作与新证据。一次假设失败不自动终止整个研究方向，也不能为使候选通过而改变用户的成功标准。
