# 优化任务

[English](README.md) | 简体中文

这里定义常用优化任务的目标、范围、约束与交付结果。用[任务模板](../templates/task-template_zh.md)填写模型、资源、负载与目标，按[通用流程](../README_zh.md#使用步骤)执行。研究方法见[元知识](../guidance/meta-knowledge/README_zh.md)，技术原理与已有经验见[知识库](../guidance/knowledge/README_zh.md)。

## 自主执行

在任务范围和资源预算内持续推进，以目标达成和实测结果作为完成依据。主 Agent 构思方向，统一负责环境准备、部署与并行实验和最终验收；Worker 研究开发候选并分析返回结果。执行边界与协作方式遵循[共用角色约定](../../.agents/skills/rsi/SKILL_zh.md#组建团队与派工)。

- 有历史实验时，先阅读已有记录，核对条件，承接保留方案、已排除的方向和未解决的问题。复用可比结果，把资源投入新问题；因条件变化或证据不足而复测时，说明本次要确认什么。
- 构建、部署、测量、记录与对照优先复用已有工具。遇到反复出现的障碍，主 Agent 区分使用和环境问题与框架缺陷，在任务范围内将值得修复的代码问题交给 Worker，验证受影响的流程后复用。
- 主动完成调查、设计、实现、部署、评测与结果分析；调查时联网查阅相关论文、官方文档与上游实践，结合当前实现形成方案。自行解决能够处理的问题，继续执行已经明确的后续工作。
- 每轮根据证据选择下一步。方案无效时分析原因、调整或换一种方案；得到局部收益后，继续检查距目标还有哪些差距。
- 将任务列出的全部节点纳入资源安排，逐台确认可用 GPU、CPU 和内存，并按实验需求分配独立候选。持续检查各节点的实验进展与 GPU 利用率，有空闲资源和待测候选时及时安排实验；节点未使用时记录原因并处理可解除的阻塞。协调共享资源，保持结果可比。
- 按任务的并行数量要求持续安排有效工作。子 Agent 完成后及时处理结果、续派任务，实验结束后及时安排下一候选；等待测量时推进独立的调查与实现，工作阻塞时调整分工。活跃子 Agent 数按正在执行的任务统计。
- 按可独立推进的研究问题派工，明确范围、预算和预期开发结果。Worker 修改独立候选 worktree，主 Agent 从交付版的对应工作区同步并执行。运行期间不改源码，继续开发时使用其他工作区或等待主 Agent 释放原工作区。成员在交接后继续协作，及时交流影响其他方向的发现。问题得到回答或无法在原范围内推进时，由主 Agent 安排后续任务与跨方向集成。
- 每项实验回答具体问题并支持一个决定。已有结果足以回答时直接复用，解释尚不明确时选择有针对性的对照。请求量和测量窗口以能作出判断为准，波动、尾延迟或稳定性需要进一步判断时再增加样本或重复测量。
- 将代码改动、服务启动和单次测试视为过程进展，而不是任务完成。结论应有实际负载下的测量结果支持；改动影响生成行为时，再评估回答质量。
- 记录与报告更新、保留方案验证和闲置资源清理随迭代进行，与独立研究和实验并行。临近截止时，根据已观察到的耗时与依赖，选择剩余预算内能完成分析与交付的有效工作，持续推进到任务结束条件满足。结束时说明目标达成情况、保留的改动、结果位置，以及剩余阻塞和恢复工作所需条件。
