# 执行 RSI 任务

[English](SKILL.md) | 简体中文

## 明确任务

只有用户要求执行或恢复时才启动实验。先阅读仓库规范、任务、[团队协作说明](roles/common_zh.md)和相关记录，区分标注 `【不可修改】` 的要求与起始实现选择。

主 Agent 建立目标、原始 baseline、资源总量、硬截止时间和初始职责，在初始化时补齐缺少的任务设置。恢复时保持原截止时间，先检查已有作业和结果。随后主 Agent 查看已有进展，将具体纠错直接交给负责人，并向用户简要汇报有效收益、采用配置、阻碍和下一步。简报使用已有报告、结果与 Evaluator 结论，不再向全员收集一轮状态。成员持续工作，不等待主 Agent 阅读、回复或批准；实验记录和导出仍由产物负责人维护。

观察没有新证据时，主 Agent 选择一个未解的协调任务：核验资源或 Hook、对齐报告与主线谱系、检查 Scheduler，或准备下一阶段 preflight；可以做只读分析和文档修正，但不重复成员的实验或审查。同时检查过期责任、重复范围和缺失的累计父版本。

启用任务的[接续绑定](continuation_zh.md#启用本次任务)，按配置启用定期巡查。同一研究课题使用一个 W&B project，名称以 `foretoken-` 开头并包含模型、硬件和目标，恢复时沿用命名。研究、实现和环境准备同时开始。任务需要在主 Agent 回合结束后继续时，启动绑定该任务的 [Agent Scheduler](continuation_zh.md#运行独立-agent-scheduler)；Hook 和 queue 只持久化职责，不会唤醒 idle 原生 thread。显式暂停、完成、过期或截止时停止 Scheduler。

Lead 保留一个观察 checkpoint，只汇报状态变化、具体纠正和决定。已确认且没有新证据的等待无需重复汇报，等下一次排期检查或 Scheduler 事件。

各 Experimenter 写自己的迭代结果和判定并刷新生成进展视图。指定一名总览负责人在报告锁内维护元数据、状态、链接和简短说明；[报告维护流程](../../../rsi-playbooks/experiment-records_zh.md#持续维护用户报告)通过现有绘图入口生成数值汇总。

## 组建团队与派工

遵守任务分别指定的 Explorer、Worker 和 Experimenter 并行人数，均不包含主 Agent。Explorer 省略或留空时默认 4；Worker 和 Experimenter 未填写时，在初始化时确定。Evaluator 数量是每轮新建人数，默认 1，设为 0 就关闭巡查。创建成员时传入任务指定的模型和推理强度，记录实际身份与角色。遵守运行环境的并发上限，如实说明人数不足的原因。

向成员交付完整研究职责，以及任务、角色、当前采用源码与证据的位置。新 Explorer 不继承主 Agent 的对话，后续阶段沿用已有研究上下文。没有专职角色的职责可以明确兼任，不把主 Agent 当隐形补位者，不为凑人数制造工作；真实等待和容量限制如实记录。

[Explorer](roles/explorer_zh.md) 用 [PGE](../../../rsi-playbooks/guidance/meta-knowledge/03-exploration-and-decision_zh.md) 选择能改善当前最优可用配置的研究方向，[Worker](roles/worker_zh.md) 实现和解释候选，[Experimenter](roles/experimenter_zh.md) 领取就绪实验、保存结果并释放资源。成员通过[接续机制](continuation_zh.md)发布和领取工作，利用课题与环境熟悉度复用上下文，不固定搭档，不把就绪任务预留给忙碌成员。

[Evaluator](roles/evaluator_zh.md) 同时独立检查推理研究及其工作流程，从变化的证据与开放问题提出可验证改进，沿同一负责人路径推进。每轮新建成员，不继承对话或载入保存的模型上下文，只提供任务、角色说明和工作目录；它自行定位记录，将发现直接交给相关负责人。

## 定期检查团队状态

初始化时按任务的间隔和 Evaluator 数量配置已有定期巡查机制，恢复时保持原计时起点。可用的已登记成员领取到期派发工作，创建要求的全新 Evaluator，实际评估保存后再用其文件完成这项工作。这不赋予该成员团队调度或结果转抄职责。

工作池排期是任务唯一的评估时间表，由仍在运行的成员消费到期派发工作。阻塞领取在工具内等候，不产生独立后台运行环境，运行能力不可用时如实说明。不用提醒再开第二套评估排期，不堆叠巡查，也不为腾名额打断实验。

巡查关注变化的证据、重要当前问题及尚未闭环的发现；初始化、重大变更和收尾时检查系统整体。发现直接交给能在授权内处理的负责人，不要求主 Agent 日常反思或批准。

## 隔离候选工作区与执行

复用已安装平台、兼容运行及编译镜像、模型文件与保留的缓存。每个候选分别拥有 worktree、可写构建状态、部署实例、运行缓存及设备分配。同一个准备好的平台可以供多个 worktree 并行使用；只对真正冲突的资源排队，由相关 Experimenter 使用现有 Kubernetes 资源机制协调。

按[增量部署流程](../../../docs/deployment/source_zh.md#部署模型服务)，通过 `-e` 指向候选工作区。模型及原生依赖在服务器中使用兼容镜像编译，允许轻量本地分析。测量前确认改动已生效，运行中的候选源码保持不变，后续开发可在另一 worktree 继续。

## 推进迭代

所有研究、探索与实现默认基于任务及负载适用的最新已验证采用配置。候选开始前读取它，在笔记记录实际父配置与本次改动；旧基点只用于明确的复现或归因问题。准备期间采用配置有更新时，整合有关改动并验证受影响行为。已经开始运行的源码和原始结果不改写。

分支有价值时，回到最新采用组合进行测量；同父兄弟候选各自有收益，不能证明两者叠加也有收益。保留原始 baseline 作为比较参照。研究负责人在任务授权与总预算内选择下一假说、实现和有信息价值的实验，并决定局部继续、停止和采用；阶段软估计可以调整，硬截止时间保持不变。

发布完整问题或有信息价值的阶段，将代码、证据和比较条件写在现有笔记。合格空闲成员直接领取，不固定 Worker–Experimenter 搭档。完成后保存原始产物并直接交付，已知空闲使用者能够继续时用原生 follow-up 恢复它。继续不受影响的工作，不等待主 Agent 重新派工。

采用前，由未参与实现和运行的 fresh Evaluator 检查。继承仍适用的验证，只针对重要变化行为安排新检查，不默认为每个候选反复安排对照或全矩阵，遵守任务明确的禁测要求。研究负责人结合评估与任务条件决定采用或修改，组合后的部署仍需有支撑其结论范围的证据。

Experimenter 在资源总预算内协调实际冲突。反复发生的执行缺陷由相应负责人修复，并验证受影响流程。只有超出授权目标、资源总预算或固定要求的变化，才通过主 Agent 用户入口取得新授权。

## 采集 GPU 使用情况

Experimenter 在分配的 GPU 主机上运行本 skill 的 `scripts/gpu_usage.py`。主机需要 Python 3.11+，并安装 `nvidia-smi` 或 `mx-smi`；脚本本身只使用标准库。没有仓库工作区的主机只需复制该脚本。采集应通过任务专属的持久会话或已有任务管理器启动，以便在成员分析结果或 SSH 断开时继续运行。

从各主机的仓库根目录执行下列命令前，将 `GPU_RUN` 设为实验结果下的新目录，`GPU_INDICES` 设为本任务使用的宿主 GPU 序号，多个序号用逗号分隔。`DEADLINE` 使用任务的绝对截止时间，并带上 UTC 时区偏移。

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py collect \
  --output "$GPU_RUN" --gpus "$GPU_INDICES" --deadline "$DEADLINE"
```

采集器会打印 PID 和输出目录，默认每 10 秒向 `samples.jsonl` 追加记录；需要改变间隔时，使用 `--interval`。脚本会自动选择已安装的设备工具，主机同时安装两种工具时，可用 `--backend nvidia` 或 `--backend metax` 指定。只有任务使用全部可见 GPU 时才省略 `--gpus`；没有时间预算的任务才省略 `--deadline`。恢复采集时使用新目录，以保留之前的记录。

分析一段已经结束的时间窗口时，将 `WINDOW_START` 和 `WINDOW_END` 设为对应的 ISO 时间。下列命令读取原主机、共享存储或本地副本中的采样，不会中断正在进行的采集。

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py summarize "$GPU_RUN" \
  --since "$WINDOW_START" --until "$WINDOW_END"
```

如果窗口包含多段采集，应传入所有对应目录，包括恢复后的采集目录。命令会按节点和 GPU 汇总时间加权利用率，并避免重复计算重叠或复制的记录。解释结果时，还应检查覆盖率、数据是否及时和查询错误；缺少采样的时段保持未知。

不再需要采集时，在采集主机上执行：

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py stop "$GPU_RUN"
```

停止标记、截止时间或 SIGINT、SIGTERM 都会让采集器在当前查询结束后退出，单次查询最多等待 10 秒。负责人应确认最后的 `end` 记录和进程退出，再释放采集器，并保留样本供报告使用。手工停止进程时，需要核对身份，避免误停已复用 PID 的进程或共享监控。

## 暂停与结束

用户要求暂停、停止，或者任务到期、完成时，停止领取新工作。各负责人停止或明确移交自己的作业与采集器，确认退出并保存结果，按任务要求保留可复用环境和缓存。通过[接续机制](continuation_zh.md#等待暂停与结束)记录任务状态；队列记录不代表有活跃成员或运行作业。

各负责人完善已有实验笔记和判定，使[报告流程](../../../rsi-playbooks/experiment-records_zh.md#持续维护用户报告)反映实际成果、采用改动与未完成验证。通过用户入口交付报告路径。
