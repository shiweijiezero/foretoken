# 执行 RSI 任务

[English](SKILL.md) | 简体中文

## 明确任务

阅读仓库规范、用户提供的任务和相关实验记录。按当前问题查阅[研究资料](../../../rsi-playbooks/guidance/README_zh.md)，链接以本 skill 目录为起点。

用户要求执行或恢复任务时才启动实验。新任务记录起始时间和截止时间；恢复时沿用原预算，先查看已有作业。任务提供的配置是可以继续修改的起点；未提供时，记录一个初始方案用于比较。承接有用的发现和未解问题，持续研究到任务规定的结束条件满足。

分配资源前，检查任务中的全部节点及其现有使用者，同时考虑模型、准备任务和评测客户端的需要。节点暂时无法使用时，记录原因并处理能够解决的问题。

W&B 按持续研究的课题建立 project，名称以 `foretoken-` 开头，并包含模型、硬件和目标，例如 `foretoken-qwen35-metax-inference`。每次实验使用一个带日期或实验名的 group，run 名称区分方案、负载和重复测量。恢复时沿用原名称，在实验记录中保存链接。

## 组建团队与派工

主 Agent 构思研究方向、分配问题和资源，并决定保留哪些方案。成员围绕完整问题开展工作，不逐条等待命令。分配任务、交接资源和独立检查结果的方式见[团队协作说明](roles/common_zh.md)。

| 角色 | 主要工作 |
| --- | --- |
| 主 Agent | 协调共享变更、综合发现、阅读保留方案的代码，负责最终验证与交付 |
| [Advisor](roles/advisor_zh.md) | 探索技术机制和新方法，发现问题并反思当前方向；至少两名成员开展互补研究 |
| [Worker](roles/worker_zh.md) | 研究和实现方案，根据结果继续改进；至少一名成员跟进完整执行流程 |
| [Experimenter](roles/experimenter_zh.md) | 构建评测、观察资源、记录结果并清理环境；按评测容量安排人数 |

提供任务、角色说明、代码和证据的绝对路径，并交代参考方案和相关决定，由成员自行阅读原文。成员使用 `worker-01`、`experimenter-01` 等稳定名称，角色前缀为 `lead`、`advisor`、`worker` 和 `experimenter`。运行环境已指定主 Agent 消息地址时，沿用该地址。

主 Agent 根据实际进展和团队协作说明中的统计方式，维持任务要求的工作人数。分别查看准备中、等待评测和执行中的候选，结合耗时和积压调整两阶段并发。结果返回后及时安排下一项工作；最终隔离测量期间，其他成员继续不争用相应资源的研究与分析。

## 隔离候选工作区与执行

在任务分支上工作，并行写入者使用不同工作区。需要独立执行目录时可以分别 clone；在同一目录切换分支不能隔离同时进行的修改。主 Agent 记录源码版本、路径、写入者和资源分配。

按[源码部署指南](../../../docs/custom-deployment_zh.md)统一准备 CLI 和共享平台。共享控制器、CRD、驱动和安装变更由主 Agent 协调。各方案使用独立的部署、可写缓存和结果目录，适合时复用只读模型数据。

执行者从候选工作区及其 Kustomize namespace 运行。从其他目录执行时，用 `-e` 指定工作区，并提供部署目录的绝对路径。修改引擎时用 `--engine-source` 指定候选引擎源码，后续运行沿用记录的选择和增量构建。

构建和测量期间保持交付代码与运行环境不变。远端使用任务专属会话或已有任务管理器保存日志与退出状态，断连后先查看原作业。需要保留的改动和结果已保存、使用者退出后，再释放或删除工作区及相关资源。暂停时保留未完成工作，提交前检查 Git 索引。

## 推进迭代

1. 结合代码、研究资料和已有结果，选择值得回答的问题。使用现有[实验命令](../../../benchmarks/docs/recipes_zh.md)、示例和 CLI help，在执行前安排好对照和资源。
2. Worker 实现并解释方案，Experimenter 构建和测量，确认改动确实生效。固定的负载组合和重复测量用 sweep 连续执行。
3. 结果直接交给开发者和审查者。其他评测进行时，继续准备和分析，并及时更新实验记录。
4. 主 Agent 在保留或集成改动前，阅读实现及相关调用代码，结合独立检查的意见作出决定。组合后的方案仍需在任务负载下验证，必要时安排无竞争测量。
5. 随新发现调整方向和资源。反复出现的执行问题交给相应负责人修复，确认受影响的流程恢复正常后再继续使用。

## 采集 GPU 使用情况

在每台 GPU 主机上使用本 skill 的 `scripts/gpu_usage.py`，需要 Python 3.11+ 及已安装的 `nvidia-smi` 或 `mx-smi`。脚本只依赖标准库；主机没有 checkout 时只需复制该脚本。使用现有远端任务管理器或本任务专属的持久 shell 会话，让采集在执行者分析期间及 SSH 断开后继续运行。

在各主机的仓库根目录，将 `GPU_RUN` 设为实验结果下的新运行目录，`GPU_INDICES` 设为该节点分配给本任务的宿主 GPU 序号（逗号分隔），`DEADLINE` 设为带 UTC 偏移的绝对 ISO 截止时间。启动一次：

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py collect \
  --output "$GPU_RUN" --gpus "$GPU_INDICES" --deadline "$DEADLINE"
```

采集器打印 PID 和输出目录，此后默认每 10 秒向 `samples.jsonl` 追加数据。用 `--interval` 调整采样间隔。脚本自动选择已安装的设备工具；两种工具都存在时，用 `--backend nvidia` 或 `--backend metax` 指定。仅在任务拥有全部可见 GPU 时省略 `--gpus`，仅在任务没有时间预算时省略 `--deadline`。已有采样文件不会被覆盖，恢复采集使用新目录。

定期分析时，将 `WINDOW_START`、`WINDOW_END` 设为下一个已完成窗口的 ISO 时间。可在原主机、共享存储或执行者机器上的记录副本中读取数据；汇总不会启动或中断采集：

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py summarize "$GPU_RUN" \
  --since "$WINDOW_START" --until "$WINDOW_END"
```

传入同一时间窗口内的各段采集目录，包括恢复后的目录。命令按节点和 GPU 汇总时间加权利用率，重叠或复制的数据不重复计数。结合覆盖率、数据新鲜度和查询错误判断结果；缺失数据保持未知，不计为空闲。

在采集主机上请求停止：

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py stop "$GPU_RUN"
```

停止标记、截止时间、SIGINT 或 SIGTERM 会使采集在当前查询完成后退出，查询最长 10 秒。确认最后的 `end` 记录及进程退出，再释放采集器。保留原始数据用于实验报告；恢复时使用新目录。不向已复用的 PID 发送信号，也不停止共享监控。

## 暂停与结束

用户要求暂停、停止，或任务到期时，停止安排新实验并通知团队。各负责人停止自己的进程，确认退出；暂停时保留未完成工作，任务结束时保存所需结果，再清理不再使用的资源。

按[实验记录手册](../../../rsi-playbooks/experiment-records_zh.md)完成任务要求的交付。主 Agent 检查保留的改动和实测结果，结合采样覆盖率与未解决的问题，说明本轮实际达到的目标。
