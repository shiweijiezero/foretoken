# 执行 RSI 任务

[English](SKILL.md) | 简体中文

## 明确任务

所有角色开始工作前，都应先[熟悉 Foretoken](roles/common_zh.md#先熟悉框架)。各成员还应阅读仓库规范、用户提供的任务和相关实验记录，并按当前问题查阅[研究资料](../../../rsi-playbooks/guidance/README_zh.md)。本文件中的相对链接以 skill 所在目录为起点。

只有用户要求执行或恢复任务时，团队才启动实验。新任务需要记录起始时间和截止时间；恢复任务时，则先查看已有作业和结果，继续使用原来的时间预算。任务提供的配置是研究起点，可以根据证据继续修改；如果没有起始配置，团队先记录一个用于比较的初始方案，再逐步探索。团队沿用已有的有效结论继续研究，直到任务规定的结束条件满足。

主 Agent 分配资源前，先按[资源协调说明](roles/common_zh.md#协调资源与运行环境)核对任务涉及的节点、现有使用者和可用 GPU 窗口。节点暂时无法使用时，应记录原因，并处理能够解决的问题。

并行实验开始前，主 Agent 统一 W&B 的命名。同一研究课题使用一个 project，名称以 `foretoken-` 开头，并包含模型、硬件和目标，例如 `foretoken-qwen35-metax-inference`。每次实验使用一个带日期或实验名的 group，各次 run 再区分方案、负载和重复测量。恢复时沿用原名称，并在实验记录中保存运行链接。

主 Agent 在任务开始时按[报告维护流程](../../../rsi-playbooks/experiment-records_zh.md#持续维护用户报告)建立面向用户的 `report.md`，并指定作者，随测量结果和决定持续更新。

## 组建团队与派工

主 Agent 负责持续推进任务目标，选择研究方向、分配问题与资源，并推动有价值的发现进入实现和实验，再根据结果决定保留、改进或停止哪些方案。团队成员围绕完整的问题开展工作，能够在约定范围内连续推进，而不必逐条等待命令。具体分配和交接方式见[团队协作说明](roles/common_zh.md)。

[Advisor](roles/advisor_zh.md) 持续探索技术机制、优化方法和新的研究问题，并帮助团队反思当前方向。主 Agent 至少安排两名 Advisor 独立开展研究。Advisor 可以探索不同问题，也可以从不同角度研究同一个问题，并在研究过程中持续交流发现。

[Worker](roles/worker_zh.md) 研究具体问题并实现候选方案，再根据实验结果继续改进。至少一名 Worker 应跟进完整执行流程，以便把局部改动与服务整体表现联系起来。

[Experimenter](roles/experimenter_zh.md) 负责构建和评测准备好的方案，同时观察资源使用、保存结果并清理实验环境。主 Agent 根据评测容量安排人数。

派工时，主 Agent 提供任务、角色说明、代码和证据的绝对路径，并交代参考方案及相关决定，由成员自行阅读原文。成员沿用 `worker-01`、`experimenter-01` 等稳定名称，角色前缀为 `lead`、`advisor`、`worker` 和 `experimenter`。如果运行环境已经指定主 Agent 的消息地址，团队就使用该地址通信。

执行期间，主 Agent 根据实际进展维持任务要求的工作人数，并查看准备中、等待评测和正在评测的候选数量。准备与评测的并发可以分别调整，具体取决于实际耗时、排队情况和剩余预算。

## 隔离候选工作区与执行

每名 Worker 使用独立工作区、任务分支和固定实例名，跨轮复用。交付的版本在构建和评测期间保持不变，具体安排见[候选交接](roles/common_zh.md#分开候选准备与评测)。

按[迭代流程](../../../rsi-playbooks/README_zh.md#复用环境持续迭代)选择部署方式。只调整参数时，复用已安装的应用；修改代码时，准备一次源码平台，涉及共享平台更新则与管理员协调。首次准备解决依赖、模型与数据集访问，后续复用平台和构建缓存。

日常 Go、Rust、Python 改动通过 `deploy -e` 指定候选源码目录，增量更新。Foretoken 会选择需要重建的应用和环境。候选沿用[并行源码部署](../../../docs/deployment/source_zh.md#并行运行候选方案)，部署与评测使用同一个实例名。

各候选选择同一个共享[数据目录](../../../docs/features/model-storage_zh.md)复用模型下载，运行缓存和结果分别保存。任务仍需要起始模型时，空闲实例用 `foretoken stop` 暂停，任务结束再用 `foretoken delete` 删除。

## 推进迭代

每轮开始时，主 Agent、Advisor 和 Worker 结合代码、研究资料和已有结果，选择值得回答的问题，并讨论用什么比较来验证。主 Agent 根据对目标负载的潜在收益、已有证据、实现与测量成本安排优先级，为深入当前方法和验证替代方法分配资源。执行方式优先参考现有[实验命令](../../../benchmarks/docs/recipes_zh.md)、示例和 CLI help，资源和对照条件应在运行前安排好。

准备或测量受阻时，主 Agent 指定负责人解决阻塞，让其他成员继续不依赖该结果的研究、实现或局部验证。尚无完整 baseline 或 profile 时，可以先准备有依据的候选及其验证方法，再根据实测决定是否采用。

Worker 实现并解释方案后，Experimenter 负责构建和测量，确认实验实际使用了预期改动。固定的负载组合和重复次数可以交给 sweep 连续执行。结果直接返回给开发者和审查者，让他们在其他评测进行期间继续分析、准备方案并更新记录。

决定保留或集成改动前，主 Agent 阅读实现及相关调用代码，并结合独立检查的意见作出判断。组合后的方案仍需在任务负载下验证。

主 Agent 持续结合研究发现和实验结果调整方向与资源安排。收到 Advisor 对研究停滞或方向偏离的提醒时，回到任务目标、当前认识和已有结果，说明继续、调整或停止的决定，并明确下一步工作与负责人。对于反复出现的执行问题，由相应负责人修复，确认受影响的流程恢复正常后再继续使用。

## 采集 GPU 使用情况

Experimenter 在分配的 GPU 主机上运行本 skill 的 `scripts/gpu_usage.py`。主机需要 Python 3.11+，并安装 `nvidia-smi` 或 `mx-smi`；脚本本身只使用标准库。没有仓库工作区的主机只需复制该脚本。采集应通过任务专属的持久会话或已有任务管理器启动，以便在成员分析结果或 SSH 断开时继续运行。

从各主机的仓库根目录执行下列命令前，将 `GPU_RUN` 设为实验结果下的新目录，`GPU_INDICES` 设为本任务使用的宿主 GPU 序号，多个序号用逗号分隔。`DEADLINE` 使用任务的绝对截止时间，并带上 UTC 时区偏移。

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py collect \
  --output "$GPU_RUN" --gpus "$GPU_INDICES" --deadline "$DEADLINE"
```

采集器会打印 PID 和输出目录，默认每 10 秒向 `samples.jsonl` 追加记录；需要改变间隔时，使用 `--interval`。脚本会自动选择已安装的设备工具，主机同时安装两种工具时，可用 `--backend nvidia` 或 `--backend metax` 指定。只有任务使用全部可见 GPU 时才省略 `--gpus`；没有时间预算的任务才省略 `--deadline`。恢复采集时使用新目录，以保留之前的记录。

分析一段已经结束的时间窗口时，将 `WINDOW_START` 和 `WINDOW_END` 设为对应的 ISO 时间。下列命令读取原主机、共享存储或本地副本中的采样，不会中断正在进行的采集。

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py summarize "$GPU_RUN" \
  --since "$WINDOW_START" --until "$WINDOW_END"
```

如果窗口包含多段采集，应传入所有对应目录，包括恢复后的采集目录。命令会按节点和 GPU 汇总时间加权利用率，并避免重复计算重叠或复制的记录。解释结果时，还应检查覆盖率、数据是否及时和查询错误；缺少采样的时段保持未知。

不再需要采集时，在采集主机上执行：

```bash
python3 -I .agents/skills/rsi/scripts/gpu_usage.py stop "$GPU_RUN"
```

停止标记、截止时间或 SIGINT、SIGTERM 都会让采集器在当前查询结束后退出，单次查询最多等待 10 秒。负责人应确认最后的 `end` 记录和进程退出，再释放采集器，并保留样本供报告使用。手工停止进程时，需要核对身份，避免误停已复用 PID 的进程或共享监控。

## 暂停与结束

用户要求暂停或停止，或者任务到期时，主 Agent 停止安排新实验并通知团队。各负责人停止自己的进程，确认退出；暂停时保留未完成工作，任务结束时保存所需结果，再清理不再使用的资源。

主 Agent 检查保留的改动和实测结果，包括采样覆盖率与未解决的问题。作者按[报告维护流程](../../../rsi-playbooks/experiment-records_zh.md#持续维护用户报告)更新已有报告，写清暂停或结束时的实际状态与已达到的目标，并向用户提供报告路径。
