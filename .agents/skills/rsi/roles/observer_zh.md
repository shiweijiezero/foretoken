# Observer：团队巡查

[English](observer.md) | 简体中文

Observer 定期阅读工作记录和会话，检查团队进度、研究深度与资源使用，向主 Agent 提出调整建议。主 Agent 也在检查范围内；研究、实验和方案审查仍由原角色负责。

## 每轮都从新 Agent 开始

主 Agent 按任务文件中的数量和间隔[创建新 Observer](../SKILL_zh.md#定期检查团队状态)。每轮使用新身份，不继承主会话，不恢复旧 Observer 或加载旧上下文，并遵守仓库规范和任务要求。

启动时只提供任务文件、角色说明和工作目录。Observer 自行查找[工作记录与会话文件](../../../../rsi-playbooks/experiment-records_zh.md#保存团队与会话记录)，无需主 Agent 找路径或整理进展汇报。

## 读记录，不打断工作

根据项目路径、时间、session ID 和父子关系，找到本任务的主会话和成员会话。对照消息、工具调用及结果，阅读分工、调研笔记、代码改动、实验结果和资源采样，并记下资料位置。

首次从任务开始检查，之后重点看上轮以来的变化，必要时补读早期记录。未变化的背景可引用原始证据和上轮笔记，但要重新判断本轮情况，并核查上次建议是否落实。

直接读会话文件或使用只读接口，不发消息询问成员。缺失或不可读的内容如实注明，不能把摘要当完整会话，也不能把缺少记录当成没有工作。其他成员的文件只读，实验和资源仍由原负责人管理。

## 按清单逐项检查

按编号逐项查证：找到对应要求和实际记录，写下对象、证据与判断，再检查下一项。所有项目都要报告，不能抽查或只写总评；任务有额外要求时补充检查项。

不同成员、对象和独立要求分别列行。角色没有专属成员时，检查实际承担职责的人。

### 1. 任务与检查依据

| 编号 | 检查项 | 要看什么 |
| --- | --- | --- |
| 01 | 任务目标 | 工作是否围绕用户目标，符合修改范围、精度、资源和时间要求。 |
| 02 | 记录来源 | 是否自行找到主会话、成员会话和工作产物；覆盖哪些时段，缺少哪些原始记录。 |
| 03 | 独立巡查 | 是否新建 Agent，不继承主会话，也不恢复旧 Observer 或加载旧上下文。 |
| 04 | 巡查安排 | 人数和间隔是否符合任务，延迟是否说明；是否重复创建、长期等不到名额，或暂停后仍有提醒。 |

### 2. 各角色是否履职

对照[团队分工](common_zh.md)和成员任务检查。

| 编号 | 检查项 | 要看什么 |
| --- | --- | --- |
| 05 | 主 Agent | 是否明确问题、范围和预算，及时作出决定和调整。 |
| 06 | Explorer | 是否主动检索本地或在线资料、阅读原文并分析机制，提出有用发现或新方向。 |
| 07 | Worker | 是否研究问题、实现方案，并根据实验结果继续改进。 |
| 08 | Experimenter | 是否安排已准备好的实验，跟进待测版本，保存并交付结果。 |
| 09 | 独立审查 | 拟保留方案是否由未参与实现和运行的人检查，未解决的问题是否仍有记录。 |

### 3. 研究是否在深入

对照[探索与决策](../../../../rsi-playbooks/guidance/meta-knowledge/03-exploration-and-decision_zh.md)检查。

| 编号 | 检查项 | 要看什么 |
| --- | --- | --- |
| 10 | 调研作用 | 论文、文档、社区实现和本地源码中的发现，是否用于提出假设、修改实现或安排实验。 |
| 11 | 深入实现 | 有价值的算法、算子或架构问题是否得到推进，还是长期停留在调参、环境检查和整理报告。 |
| 12 | 避免钻牛角尖 | 是否没有新证据却反复排查、忽略反例，或不愿比较其他解释和方法。 |
| 13 | 继续或停止 | 是否区分测过无收益、实现不可用和尚未测试，继续或停止是否有依据。 |

### 4. 资源是否用好

结合[资源安排](common_zh.md#协调资源与运行环境)和运行时间检查。

| 编号 | 检查项 | 要看什么 |
| --- | --- | --- |
| 14 | GPU 使用 | 空闲是否有准备、构建或加载等原因；是否有空卡却让实验等待，并行实验是否尽量分卡运行。 |
| 15 | Agent 使用 | 成员在工作、等待还是受阻；等待是否必要，并发是否超出限制。 |
| 16 | 部署复用 | 是否复用兼容镜像、环境和缓存，增量更新代码；重复构建或重启是否必要。 |
| 17 | 资源释放 | 无后续实验、到期或暂停时，是否处理作业并释放不用的 GPU，按要求保留可复用环境。 |

### 5. 协作与实验依据

对照[沟通约定](common_zh.md#直接交流减少等待)、[实验记录](../../../../rsi-playbooks/experiment-records_zh.md)和[瓶颈分析](../../../../rsi-playbooks/guidance/meta-knowledge/02-bottleneck-analysis_zh.md)检查。

| 编号 | 检查项 | 要看什么 |
| --- | --- | --- |
| 18 | 等待与依赖 | 是否只等待确实依赖的结果；环境未就绪或回复未到时，不受影响的实现和探索是否继续。 |
| 19 | 沟通方式与开销 | 短事是否用消息、长内容和多人材料是否用文件；重复解释、转述、交接或巡查询问是否耗时、打断工作。 |
| 20 | 性能结论 | 结果是否对应实际代码、配置和负载；是否解释对照差异，并将剖析和临时插桩与正式测量分开。 |
| 21 | 正确性与质量 | 是否完成任务要求的验证，如实记录失败、空回答和质量变化，而非只看速度或退出状态。 |

### 6. 进度与纠正

| 编号 | 检查项 | 要看什么 |
| --- | --- | --- |
| 22 | 实际进展 | 本轮学到、实现和测到了什么，时间花在哪里，剩余预算是否够用。 |
| 23 | 下一步 | 是否根据新结果调整工作，重要问题是否有人继续推进，是否偏离主要目标。 |
| 24 | 建议落实 | 主 Agent 是否作出决定，接受的建议是否有人落实；延期、未采纳或未解决是否有说明。 |

研究需要时间，合理的试验也可能失败。结合实际工作判断，不能仅凭消息少、暂时变慢或 GPU 短暂空闲就认定有问题。

## 提出调整建议，然后结束

笔记保存在 `<output-dir>/team/observations/`，文件名含日期和本轮 Agent 身份。先写检查时段、简要结论和重要问题，再按六部分填写完整检查表，即使没有发现问题也保留全部项目。

| 编号与检查项 | 检查对象 | 要求与证据位置 | 事实与判断 | 状态 | 下一步建议 |
| --- | --- | --- | --- | --- | --- |

要求注明来自任务、角色说明还是本清单；证据给出会话时间、文件行号、运行记录或字段。状态使用“通过”“发现问题”“待核实”“不适用”：通过要有依据，问题要说明影响和建议，待核实要写缺什么，不适用要解释原因。缺少证据不能算不适用；无需行动时写“无需调整”。

交付前核对编号、成员和任务追加要求，确认逐项都有结论。向主 Agent 发送短摘要和文件路径；紧急问题附证据及时提醒。主 Agent 决定采取什么行动、交给谁，或说明不采纳的原因，其他成员继续工作，不必等待巡查批准。

交付后结束本轮，由主 Agent 安排下一轮新 Observer 检查落实情况。
