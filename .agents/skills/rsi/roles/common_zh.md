# RSI 团队协作

[English](common.md) | 简体中文

主 Agent 建立目标、固定条件、原始 baseline、总预算和初始团队。随后各成员在这些授权内负责研究、实现和实验；独立采用审查由全新的 Evaluator 完成。Agent Scheduler 运行后，主 Agent 查看记录、资源和研究边界，针对具体缺口提醒负责人并向用户简要汇报，不逐阶段派工或转发日常消息。观察与用户更新规则统一写在 [RSI skill](../SKILL_zh.md) 中；成员不等待主 Agent 的消息。Scheduler 不可用或 lease 卡住时，主 Agent 先核对原生活动，只修复或重建缺失成员，重新登记其完整职责，并用原生 follow-up 修复调度，不接管研究。日常决定与交付直接到达实际使用者。

## 先熟悉框架

阅读[项目 README](../../../../README_zh.md)、架构说明和受影响路径的文档，再阅读任务、当前采用配置及相关实验记录。修改行为前追踪完整的生产与消费路径。复用已有理解和仍适用的证据，只按当前问题或版本变化补充阅读。

## 分配完整的问题

围绕完整研究问题持续负责调查、实现和结果解释，不在每个阶段后等待重新派工。负责人在任务目标与总预算内选择下一假设、调整阶段估计，并决定继续、修改或停止。重要机制应获得必要实现时间，不能只推进已经就绪的小改动。

问题、已有认识、代码、比较条件与预期证据保存在现有迭代笔记。通过[接续机制](../continuation_zh.md)提交完整问题或有信息价值的阶段，由具备相应能力的空闲成员领取。熟悉课题或环境有利于复用上下文，但不固定 Worker–Experimenter 搭档，也不把工作预留给忙碌成员。没有专职角色的职责明确兼任。遵守任务人数设置，如实记录真实依赖，不为满员制造实验。

新的研究与实现默认基于任务及负载适用的最新已验证采用版本，在迭代笔记记录实际父配置与本次变化。准备期间父配置更新时，移植相关改动并验证受影响行为；不改写已经运行中的原件。只有明确的复现或归因问题才使用旧基点。分支有收益时，将其整合到最新采用配置并测量组合；两项独立收益不能证明组合效果。原始 baseline 始终保留为比较参照。

各角色不依赖固定人数比例或搭档。无人能够执行某项必要工作时，如实记录能力缺口，其他独立工作继续。每个采用决定都由 fresh Evaluator 检查；缺少该检查时暂不采用，不由主 Agent 隐形补位。

## 直接交流，减少等待

Explorer 将有用研究直接交给实现者，Worker 将可运行候选交给可用的 Experimenter，执行者将结果和原始路径交给研究负责人，供下一轮 Evaluator 检查。审查发现交给能解决问题的人。共享背景写入现有笔记，消息只发结论、变化和准确路径，日常更新不必确认。

产物使已知的等待成员能够继续时，通过原生 follow-up 恢复该成员；Scheduler 报告 thread 为空闲时，只把它当作调度修复场景。普通消息不会唤醒空闲成员。任何合格成员都能承担的工作通过接续机制发布，不预先囤给忙碌成员。等待真实依赖期间继续不受影响的工作。

Evaluator 将发现直接交给相关负责人。负责人在授权内根据证据处理，并在对应笔记记录结果。只有超出用户授权目标、资源总预算或固定条件的变化，才通过用户入口取得新授权。

## 分开候选准备与评测

交付候选工作区与版本、问题、参照、命令、负载、资源和需要重建的部分。构建和测量期间保持待测源码不变；需要同时继续开发时，使用另一 worktree。

共享已安装的平台、兼容镜像、模型文件和可复用缓存；各候选隔离源码、可写构建状态、部署实例、运行缓存和分配的设备。同一个准备好的平台可供多个 worktree 并行使用。模型及原生依赖在服务器中复用兼容镜像和缓存编译，轻量本地分析可以正常进行。其他主机或非目标 GPU 有可用容量时，可以用于有价值的实验，但要记录准确的主机、设备并单独设定比较 scope。使用 RDMA 或 InfiniBand 时明确记录资源预留和观测；跨主机传输证据不能直接作为单机 A100 性能结论。

每个运行中的实验由一名执行者负责到结果交付与清理。更换执行者时交接原作业和原始产物，先检查现有进程再决定是否重启。需要时复用熟悉的上下文，不要求固定搭档或所有实验共用一条队列。

## 协调资源与运行环境

Experimenter 只协调实验实际竞争的资源。结合现有 Kubernetes 资源请求、调度和工作负载状态，以及宿主观察，在任务资源总预算内安排设备与节点容量，同时计入服务、构建、客户端和模型准备。共享镜像或平台不意味着独立部署必须串行。

使用设备前核对当前工作负载与授权，没有就绪实验接着运行时释放设备，保留环境、模型文件和构建缓存。资源允许时准备与测量可以并行，但成对测量窗口应排除竞争负载。环境故障由对应负责人修复，其他研究继续。

## 随实验返回结果

执行者在自己的实验记录中保存每个完成点及判断，包含失败和诊断。保留原始命令、源码和配置、请求记录与资源观察，不必等整套矩阵完成再交付。按[报告维护流程](../../../../rsi-playbooks/experiment-records_zh.md#持续维护用户报告)通过现有绘图入口汇总各自产物，不设中央作者转抄成员结果。

研究负责人解释证据，选择下一项有信息价值的工作。复用可比的已完成测量与仍适用的验证，不为每个候选惯例性地重跑一份对照、反复执行对照—候选—对照，或把每个问题扩成全矩阵；只有具体未知需要时才选择复测。任务明确的禁测条件优先。

## 独立复核结论

采用方案前，由全新的 Evaluator 检查变化的代码、实际配置和原始证据。复用已经审查的背景及仍适用的验证。重要的受影响行为用最小且有意义的比较验证；是否评分取决于输出影响与已有证据。

Evaluator 记录结论适用范围及具体未解问题。研究负责人修复、停止候选，或在满足任务要求与评估后采用。整合基于最新采用配置，并验证组合结果，这些日常决定不经主 Agent 审批。

## 交接与恢复

阶段结束时保存结果，通过[接续机制](../continuation_zh.md)发布下一项有用工作或真实依赖。交付发现或审查只完成了一项工作，不结束持续研究职责；没有其他生产者发布问题时，研究负责人仍应自主选择下一问题。空闲成员直接领取就绪工作；已有使用者的依赖结果到达时，由生产者恢复等待成员，或在修复调度时恢复 Scheduler 报告为空闲的 thread。阶段完成或软时间估计不结束仍有价值的研究职责，任务的硬截止时间保持不变。

暂停、停止或到期时，各负责人停止或交接自己的作业和采集器，确认退出并保存结果。采集器截止时间只控制采集进程，服务与构建作业需要各自停止。恢复时先检查原作业及产物，再启动替代作业。

有效工作人数使用原生活动统计，每名成员只计一次。等待、受阻和已完成成员不算正在工作，缺少证据的时段保持未知。Evaluator 只在巡查期间计入。
