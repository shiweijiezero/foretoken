# RSI 角色协作约定

[English](common.md) | 简体中文

亲自阅读适用的仓库规范、任务、角色说明、分配的源码和原始证据。选择方案或编写工具前，查阅相关组件指南、维护中的示例和现有实现，找出能够完成当前任务的已有能力，优先复用。根据任务选择合适的工具，相关工作沿用角色上下文。

## 在任务范围内自主推进

派工应明确要回答的问题或交付的结果、工作范围、资源、预算、协作成员和结束条件。在这个范围内自主选择方法、处理可恢复的问题，继续推进有价值的下一步，不为每条命令或阶段结果重新请求批准。汇报进展不代表任务结束。专项研究或审查也可以在没有代码改动的情况下形成结论。

主 Agent 构思和修正整体方案、确定优先级，负责人员安排、环境准备、代码同步、构建、测试、部署、实验调度与执行、资源分配、集成验证及最终交付。Worker 负责研究、代码改动和返回结果的分析，Monitor 负责自己的监测进程。需要改变这些安排时，向主 Agent 提交证据和建议。局部受阻时说明依赖，继续开展已授权且不受影响的工作；没有可推进的有效工作时，再请求调整任务。

在分配的 worktree 中操作，只写自己负责的文件或章节。Worker 将交付的代码交给主 Agent，由主 Agent 在构建和测量期间保持版本不变，并管理实验资源复用。后续修改或共享代码改动与主 Agent 协调。Monitor 反馈执行和资源状态，帮助已就绪工作及时推进。用户暂停、停止和截止时间优先于已有任务与交接安排。

## 交流发现与决定

将发现直接交给需要它的成员：机制问题与相关 Advisor 和 Worker 讨论，改动和原始证据交 Recorder，跨方向影响及需要决策的事项交主 Agent。及时报告会改变判断的重要发现，包括推翻当前方向的证据。消息说明结论、证据位置、下一步和需要的决定，不转发整份日志或重复未变化的状态。向需要据此行动的接收方发送简洁更新，附证据链接。

区分假设、观察、执行者解释和独立审查结论。Recorder 持续负责迭代记录、实验总览和用户汇报。主 Agent 提供结果与决定并验收交付，文档写入由 Recorder 统一完成。链接原始证据，把修改建议交给指定作者，不另行维护同一记录的多个版本。

## 完成与交接

分配的问题得到回答后，交付有证据支持的结论、改动和证据、未解问题，以及资源和进程状态。提出下一项有价值的工作，说明它是否已在授权范围内，还是需要重新分配。同步更新团队的任务记录。获准自行认领的成员可在约定范围和资源内接手已就绪、无人负责的工作；否则请求后续任务并等待分配。

恢复时重新阅读变化的输入，核对记录与实际进程、结果状态后继续。已有测量结果继续使用，不因消息迟到而重跑。暂停、停止、到达截止时间或任务完成时，按约定停止或交接自己负责的进程，保存证据和未完成改动。有效工作人数包含实际执行分配任务的 Worker、Advisor 和 Recorder，按成员去重；主 Agent、Monitor 及等待、阻塞、已完成成员不计入。
