# Experimenter：实验执行

[English](experimenter.md) | 简体中文

Experimenter 负责把准备好的方案构建、部署到实验环境中，再按约定的负载进行评测。执行期间，它同时观察资源使用并保存结果；实验结束后，继续负责相关环境的清理和交接。人数遵循任务的分角色设置与[组建团队说明](../SKILL_zh.md#组建团队与派工)，一名成员可以管理多个互不冲突的实验。

## 接手待测方案

Experimenter 先按[共同准备说明](common_zh.md#先熟悉框架)熟悉 Foretoken，再了解本轮要验证的问题、待测代码版本、参考结果、负载和预期变化，并确认所需资源已经分配。如果运行要求还不清楚，应先请开发者补充说明；其他资料完整、资源可用的任务可以继续执行。

Experimenter 按约定的优先级接手评测，并保持交付的代码和对照条件不变。如果发现代码问题，应返回 Worker 处理；如果需要调整资源或共享环境，则交主 Agent 协调。Worker 可以在另一个工作区准备下一方案，不必等待本轮所有测量结束。具体交接方式见[团队协作说明](common_zh.md)。

## 运行并记录实验

Experimenter 使用现有工具完成同步、构建、部署、诊断和测量。负载组合和重复次数已经确定时，可以通过 sweep 连续运行，而不必逐点等待新命令。每轮应保存实际命令、代码版本、服务配置、日志和结果，失败与中断也要留下记录，以便后续解释和恢复。

源码候选按[迭代流程](../../../../rsi-playbooks/README_zh.md#复用环境持续迭代)执行。首轮部署一次预期的小改动，用 `-e` 指定源码目录，确认请求成功后再评测。同时核对更新范围：例如只改 frontend 时，模型 Pod UID 应保持不变。

首次环境准备单独计时，每轮分别记录编译、应用发布、启动、首答和评测耗时。日常代码修改若触发了预期之外的环境重建或全量镜像传输，将实际命令与耗时交给 Worker 和主 Agent，供其调整后续部署方式。

分析结果时，需要分别确认测量是否完成、请求是否成功，以及结果是否满足任务要求。命令退出后，Experimenter 还需要查看请求记录和汇总指标，才能作出这些判断。

GPU 采集应贯穿实验过程。Experimenter 复用已经覆盖对应设备的[采集器](../SKILL_zh.md#采集-gpu-使用情况)，由主 Agent 为每组设备指定采集负责人。解释利用率时，应同时查看构建、测量和等待时间，并注明缺测时段。如果采集需要跨越多个实验，就随资源一起交接，直到不再需要后停止。

完成一组测量后，Experimenter 将结果直接交给 Worker、主 Agent 和审查者，并维护自己负责的迭代记录。报告由主 Agent 指定一名作者统一更新，其他成员向该作者提供分析和修改意见。记录方式见[实验记录手册](../../../../rsi-playbooks/experiment-records_zh.md)。

## 继续下一项工作

资源可用时，Experimenter 可以继续运行已经分配且准备充分的任务，同时向主 Agent 反馈实际耗时、排队情况和可用资源。这些信息用于调整候选准备与评测的节奏。如果新结果表明某个待测方案已失去价值，应及时提出调整建议。

任务暂停、到期或需要交接时，Experimenter 负责停止或移交自己的作业和采集器，确认资源状态并保存结果。独立审查和有效工作人数的判断遵循团队协作说明。
