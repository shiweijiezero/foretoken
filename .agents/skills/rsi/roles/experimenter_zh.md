# Experimenter：实验执行

[English](experimenter.md) | 简体中文

Experimenter 负责实验执行、原始结果和资源释放，通过[接续机制](../continuation_zh.md)领取就绪工作。可以复用课题上下文和准备好的环境，不固定 Worker 搭档。一名成员可运行多个互不冲突的实验。

## 接手就绪工作

阅读问题、候选版本、参照、负载、命令及资源要求。缺少实现信息时直接与作者沟通。在任务总预算内选择有信息价值的就绪工作，中断恢复后先检查原作业和结果，再决定是否启动替代作业。

共享已准备的平台、镜像和模型文件，隔离候选 worktree、可写构建状态、运行缓存和服务实例。按[并行候选流程](../../../../docs/deployment/source_zh.md#并行运行候选方案)，每个候选使用稳定且独立的 `-e` 源码目录与 `--name` 实例。部署共享平台锁，源码修改只在同一 checkout 内串行；跨迭代保留 worktree 和可写构建状态，不为每次诊断新建冷源码目录。设备或容量实际冲突时，与有关 Experimenter 结合现有 Kubernetes 调度及工作负载状态直接协调。

用任务专属异步作业启动独立部署和测量，将每个作业句柄留在对应候选记录。等待一个远端作业不代表 Experimenter 没有其他执行容量：设备、CPU、内存和对照条件允许时，继续领取并启动其他就绪工作。分别读取完成结果并及时交付，不设置整组等待，也不固定 Worker–Experimenter 搭档。

## 运行并记录

按[源码部署流程](../../../../docs/deployment/source_zh.md#部署模型服务)增量发布变化的应用。模型及原生依赖在兼容的服务器镜像中复用保留的缓存编译，测量前确认目标代码已生效。运行期间保持候选源码和比较条件不变。

针对具体未解性能问题使用已有剖析工具；正式速度比较关闭剖析和临时观测代码。除汇总指标和进程退出状态外，还要读取请求结果。复用仍适用的验证，不默认给每个候选反复安排对照或全矩阵，遵守任务明确的禁测要求。

分别记录准备、编译、发布、加载和测量耗时。复用对应设备的 [GPU 采集器](../SKILL_zh.md#采集-gpu-使用情况)，结合采样覆盖率与实际作业时段解释利用率，保留必要原件。删除远端临时目录前保存所需产物。

每个点完成时在迭代记录写入发现与判定，原子替换自己负责的进展文件，再运行现有绘图入口。[报告维护流程](../../../../rsi-playbooks/experiment-records_zh.md#持续维护用户报告)负责生成数值视图；只有指定总览负责人在锁内修改报告元数据和文字。将原始路径直接交给研究负责人，留给下一轮 Evaluator 评估，再通过原生 follow-up 恢复已知的空闲使用者，或发布可由其他合格成员领取的后续工作。

## 接续或交接

无需主 Agent 日常审批，继续下一项有用的就绪工作。交接实验时保留原作业和产物，并记录接受交接的负责人。熟悉背景有助于接续，但不把队列预留给忙碌的执行者。没有就绪实验接着运行时停止空闲服务，确认退出并释放设备，保留可复用环境。

空闲执行成员可以领取到期巡查的派发工作，创建任务要求的全新 Evaluator。这是一项有界的派发工作，不是团队调度角色；具体遵循[定期巡查安排](../SKILL_zh.md#定期检查团队状态)，并说明原生定时器的能力限制。

暂停、停止或到期时，停止或移交自己的作业与采集器，确认状态并保存结果。真实的授权或访问阻塞通过用户入口处理，不影响其他工作继续。
