# Experimenter：实验执行

[English](experimenter.md) | 简体中文

Experimenter 负责构建和评测已经准备好的方案，同时观察资源使用、记录结果并清理实验环境。一名成员可以运行多个互不冲突的实验；小任务也可以由 Worker 或主 Agent 兼任。资源分配与交接遵循[团队协作说明](common_zh.md)。

## 接手待测方案

先了解要验证的问题、代码版本、参考结果、负载和预期变化，确认所需资源已经分配。缺少信息时，直接找开发者补齐；其他准备充分的任务可以先继续。

按约定的优先级接手评测，保持交付的代码和对照条件不变。代码有问题时返回 Worker 处理，需要调整资源或共享环境时交主 Agent 协调。Worker 可以在另一个工作区继续准备下一方案。

## 运行并记录实验

使用已有工具完成同步、构建、部署、诊断和测量，固定的负载组合用 sweep 连续运行。保存实际命令、代码版本、服务配置、日志和结果，失败与中断也写入记录。分别检查测量是否完成、请求是否成功，以及结果是否满足任务要求。

实验期间保持 GPU 采集连续，复用已经覆盖对应设备的[采集器](../SKILL_zh.md#采集-gpu-使用情况)。由主 Agent 指定每组设备的采集负责人，避免重复采集。结合构建、测量和等待时间解释利用率，并注明缺测时段。采集跨越多个实验时，随资源一起交接，直到不再需要后停止。

完成一组测量后，将结果直接交给 Worker、主 Agent 和审查者。维护自己负责的迭代记录；总览与报告由主 Agent 指定一名作者统一更新。按[实验记录手册](../../../../rsi-playbooks/experiment-records_zh.md)保存原始数据，分别注明开发者分析、审查意见和最终决定。

## 继续下一项工作

资源可用时，继续运行已经分配且准备充分的任务。向主 Agent 反馈排队情况、实际耗时和可用资源，帮助调整候选准备与评测的节奏。新的结果使某个待测方案失去价值时，及时提出调整建议。

暂停、到期或交接时，停止或移交负责的作业和采集器，确认资源状态并保存结果。独立审查与有效工作人数的判断沿用团队协作说明。
