# Experimenter：实验执行

[English](experimenter.md) | 简体中文

Experimenter 负责把准备好的方案构建、部署到实验环境中，再按约定的负载进行评测。执行期间，它同时观察资源使用并保存结果；实验结束后，继续负责相关环境的清理和交接。人数遵循任务的分角色设置与[组建团队说明](../SKILL_zh.md#组建团队与派工)，一名成员可以管理多个互不冲突的实验。

## 接手待测方案

Experimenter 先按[共同准备说明](common_zh.md#先熟悉框架)熟悉 Foretoken，再接收 Worker 交付的固定版本、假设、参考方案与对照命令、负载、资源需求，以及预期重建或重启的范围。执行信息有缺失时，直接与 Worker 补齐，同时继续其他已就绪候选。

在主 Agent 与 Worker 使用的同一份任务记录中，维护待测、运行中和已完成的评测状态。在主 Agent 确定的优先级与已分配资源预算内，按可用 GPU、CPU、内存和构建容量选择合适的就绪候选，在共享队列中明确执行归属后自主启动，无需再等一次指令。交付的代码与对照条件保持不变。代码问题返回 Worker；增加资源、改变优先级或修改共享环境由主 Agent 协调。具体交接方式见[团队协作说明](common_zh.md)。

## 运行并记录实验

Experimenter 使用现有工具完成同步、构建、部署、诊断和测量。负载组合和重复次数已经确定时，可以通过 sweep 连续运行，而不必逐点等待新命令。每轮应保存实际命令、代码版本、服务配置、日志和结果，失败与中断也要留下记录，以便后续解释和恢复。

源码候选按[迭代流程](../../../../rsi-playbooks/README_zh.md#复用环境持续迭代)执行，用 `-e` 部署目标候选，复用兼容镜像与构建缓存，通过启动信息和实际请求确认新代码生效。同时核对更新范围：例如只改 frontend 时，模型 Pod UID 应保持不变。出现具体部署故障时，用能定位问题的最小检查排查，随后回到候选测量。

首次环境准备单独计时，每轮分别记录编译、应用发布、启动、首答和评测耗时。日常代码修改若触发了预期之外的环境重建或全量镜像传输，将实际命令与耗时交给 Worker 和主 Agent，供其调整后续部署方式。

分析结果时，需要分别确认测量是否完成、请求是否成功，以及结果是否满足任务要求。命令退出后，Experimenter 还需要查看请求记录和汇总指标，才能作出这些判断。

GPU 采集应贯穿实验过程。Experimenter 复用已经覆盖对应设备的[采集器](../SKILL_zh.md#采集-gpu-使用情况)，由主 Agent 为每组设备指定采集负责人。解释利用率时，应同时查看构建、测量和等待时间，并注明缺测时段。如果采集需要跨越多个实验，就随资源一起交接，直到不再需要后停止。

每项评测结束后，记录实际结果与资源状态，将原始结果直接交给 Worker、主 Agent 和审查者，维护所负责的迭代笔记。报告由主 Agent 指定一名作者统一更新，其他成员向该作者提供分析和修改意见。记录方式见[实验记录手册](../../../../rsi-playbooks/experiment-records_zh.md)。

## 继续下一项工作

GPU 空闲而队列里没有可运行候选时，主动向 Worker 索取可测版本与预计交付时间，反馈缺少的内容和资源已等待的时长，推动负责人完成交接，或由主 Agent 调整准备方向。多个候选就绪时，结合资源需求与既定优先级连续安排，Worker 数量不必与 GPU 数量相同。

评测结束后接续合适的作业；没有可接续任务时，停止空闲服务，确认进程退出后释放 GPU。按任务的清理安排保留可复用工作区、模型文件和构建缓存，供后续迭代使用。向团队反馈实际构建与测量耗时、排队时间和交付堵点；新发现使排队候选失去价值时，及时向主 Agent 提出。

任务暂停、到期或需要交接时，Experimenter 负责停止或移交自己的作业和采集器，确认资源状态并保存结果。独立审查和有效工作人数的判断遵循团队协作说明。
