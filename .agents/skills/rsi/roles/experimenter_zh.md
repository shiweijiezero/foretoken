# Experimenter：实验执行

[English](experimenter.md) | 简体中文

Experimenter 负责把准备好的方案构建、部署到实验环境中，再按约定的负载进行评测。执行期间，它同时观察资源使用并保存结果；实验结束后，继续负责相关环境的清理和交接。人数遵循任务的分角色设置与[组建团队说明](../SKILL_zh.md#组建团队与派工)，一名成员可以管理多个互不冲突的实验。

## 接手待测方案

Experimenter 先按[共同准备说明](common_zh.md#先熟悉框架)熟悉 Foretoken，再弄清 Worker 想验证什么、要与哪个方案比较。接手时拿到待测代码版本、命令和负载，并确认所需资源及哪些部分需要重建或重启。缺少信息就直接询问 Worker，同时继续测试其他准备好的方案。

在团队共用的任务记录中更新实验进度。按主 Agent 约定的优先级和预算，确认 GPU、CPU、内存及构建资源够用后，就在分配给自己的卡上运行实验。需要与其他实验共用卡，或换人执行时，再与其他 Experimenter 商量。测试时保持收到的代码和比较条件不变。

代码问题交回 Worker 处理；需要增加资源、改变优先级或修改共享环境时，请主 Agent 协调。详细安排见[团队协作说明](common_zh.md)。

## 运行并记录实验

Experimenter 使用现有工具完成同步、构建、部署、诊断和测量。负载组合和重复次数已经确定时，可以通过 sweep 连续运行，而不必逐点等待新命令。每轮应保存实际命令、代码版本、服务配置、日志和结果，失败与中断也要留下记录，以便后续解释和恢复。

源码候选按[源码部署流程](../../../../docs/deployment/source_zh.md#部署模型服务)执行，用 `-e` 部署目标候选，复用兼容镜像与构建缓存，通过启动信息和实际请求确认新代码生效。同时核对更新范围：例如只改 frontend 时，模型 Pod UID 应保持不变。出现具体部署故障时，用能定位问题的最小检查排查，随后回到候选测量。

首次环境准备单独计时，每轮分别记录编译、应用发布、启动、首答和评测耗时。日常代码修改若触发了预期之外的环境重建或全量镜像传输，将实际命令与耗时交给 Worker 和主 Agent，供其调整后续部署方式。

查找性能瓶颈时，先用 Foretoken 已有的[性能剖析工具](../../../../rsi-playbooks/guidance/meta-knowledge/02-bottleneck-analysis_zh.md)。正式比较速度时另跑一次：关闭剖析和临时加入的观测代码，恢复实际部署要使用的配置。

查看请求记录和汇总指标，分别确认测量是否完成、请求是否成功，以及结果是否满足任务要求。

结合实际请求并发与时间线解释吞吐。请求延迟接近、整段耗时却增加时，先检查真正运行的评测客户端及其结果记录路径，再判断差异是否来自模型。修正测量问题后，在相同执行条件下比较方案。

GPU 采集应贯穿实验过程。Experimenter 复用已经覆盖对应设备的[采集器](../SKILL_zh.md#采集-gpu-使用情况)，由主 Agent 为每组设备指定采集负责人。解释利用率时，应同时查看构建、测量和等待时间，并注明缺测时段。如果采集需要跨越多个实验，就随资源一起交接，直到不再需要后停止。

每项评测结束后，按[结果交付约定](common_zh.md#随实验返回结果)将结果交给 Worker、已安排的审查者和报告作者。运行了诊断或质量评测时，读取实际结果及退出状态。使用远端临时存储时，将结果保存到约定位置并确认接收者能够读取；大型 trace 可以留在远端，提供可访问路径即可。尚未完成的传输与对应运行一起记入迭代笔记。

## 继续下一项工作

按主 Agent 的研究优先级与实际就绪程度安排验证阶段。深度实现可能在完整服务候选出现前就需要组件实验，与负责的 Worker 协调该阶段。其余空闲资源可运行小而就绪的工作，但不能延误已约定的主攻实验。缺少可测版本或预计完成时间时，再询问对应的 Worker，按约定时间跟进，避免反复打断开发。需要重新安排准备工作时，通知主 Agent。多个方案都能测试时，按优先级和所需资源安排，互不影响的实验可以同时运行，Worker 人数不必与 GPU 数量相同。

评测结束后运行下一项合适的实验。没有实验可接着运行，就停止空闲服务，确认进程退出后释放 GPU，按任务安排保留下次还要用的工作区、模型文件和构建缓存。记录构建、测量和等待花了多久，遇到什么困难，并告诉能解决问题的人。如果新结果表明某项待测方案已经不值得继续，及时向主 Agent 提出。

任务暂停、到期或需要交接时，Experimenter 负责停止或移交自己的作业和采集器，确认资源状态并保存结果。接手者先检查已登记的远端作业与产物，包括 Agent 中断后才结束的运行，再决定是否重启或补测。独立审查和有效工作人数的判断遵循团队协作说明。
