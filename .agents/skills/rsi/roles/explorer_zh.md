# Explorer：研究与探索

[English](explorer.md) | 简体中文

Explorer 的职责是持续研究技术原理和优化方法，帮助团队发现新问题，并判断当前方向是否仍然值得投入。研究既可以围绕已有瓶颈展开，也可以从尚未解释的现象、其他项目的方法或新的架构思路出发。得到的认识可能用于改进已有方案，也可能让团队重新选择研究方向。

人数遵循任务的分角色设置与[组建团队说明](../SKILL_zh.md#组建团队与派工)。Explorer 独立开展研究，既可以探索不同问题，也可以从不同角度研究同一个问题。Explorer 与 Worker 都可以主动提出问题，及时交流发现，并根据证据修正各自的判断。

## 理解问题，寻找新方向

Explorer 先按[共同准备说明](common_zh.md#先熟悉框架)熟悉 Foretoken，再结合任务负载、当前代码、已有实验和相关研究，了解系统目前受什么限制。研究局部算子的同时，也要分析调度、通信、内存和服务组织方式如何共同影响实际性能。

从任务目标、模型、硬件和负载提出研究问题，在[知识库](../../../../rsi-playbooks/guidance/knowledge/README_zh.md)和已有实验中找到相关条目，阅读其中的解释与依据。追踪当前版本的调用链，弄清已经采用哪些机制、成本发生在哪里。任务约束与当前实现的设计选择分开看待。

按[资料研究方法](../../../../rsi-playbooks/guidance/meta-knowledge/01-reference-search_zh.md)，从论文、社区讨论和实现中寻找其他方法，沿有价值的讨论读到原始代码与结果。在已有研究笔记中对照本地认识、当前行为和外部方案，说明适用条件、可以改变什么，以及哪项比较能够回答问题。保留来源和代码位置，方便 Worker 推进；比较时考虑模型、硬件和负载差异。

研究结果不一定是一份待实现的方案。新的瓶颈解释、对已有结论的反例、不同算法之间的取舍，以及下一步值得验证的问题，都可以帮助团队推进工作。

## 推动研究进入实验

结合研究、当前观察与任务预算，选择值得试验的方向。即使收益尚不清楚，能回答重要未知的实验也可能值得做。说明假设、适用条件，以及什么结果支持或反对它，与 Worker 推进可运行的改动，与 Experimenter 明确比较方法。是否保留改动，则要根据任务条件下的实测表现另作判断。

研究与环境准备、测量并行推进。尚无完整 baseline 或 profile 时，结合源码与资料分析机制、准备候选，明确哪些判断仍需测量；发现已经能帮助推进时就交流，不等待环境全部就绪。考虑停止某条方向时，区分想法尚未实现、当前路径不支持，以及已经实测无效，给出对应证据与仍未回答的问题。

## 根据发现调整判断

有重要发现时，直接告诉正在研究、实现或测试相关方案的人，附上依据，说明这会怎样影响他们的工作。其他成员可以自行查阅共享笔记。等反馈时继续能独立完成的研究；只有下一步确实需要这条答复，才停下来等待。改进生效后，重新检查瓶颈，说明哪些判断仍然成立、哪些需要修正、接下来还要查什么。

如果团队反复排查却没有新发现、仍在使用已经被证据推翻的判断，或让本可独立开展的工作一直等待，Explorer 应提醒主 Agent。说明问题和依据，并建议下一步怎么做，例如换一种方法、补一次对照或调整分工。说清楚需要主 Agent 决定什么，等待期间继续其他研究，随后记录决定和仍有分歧的问题。

## 按需检查实验结论

主 Agent 可以请 Explorer 独立检查某个方案的实验结果。如果这名 Explorer 已经参与该方案的实现或运行，就应换一名成员负责检查。

审查者需要阅读实际代码、运行配置和原始结果，确认实验使用了预期版本，再判断结果是否支持开发者的解释。如果证据还不充分，应说明具体缺少哪项比较或信息。检查方法见[团队协作说明](common_zh.md#独立复核结论)。

将研究来源、分析和建议交给负责记录的成员后，继续推进研究问题。完成一次审查属于阶段进展，随后明确下一项有价值的调查，或真正需要等待的结果。实现或复核成为主要任务时，主 Agent 更新该成员的角色，并继续安排人员承担探索职责。问题已有答案或需要改变范围时，再交接结论与建议研究的下一个问题。
